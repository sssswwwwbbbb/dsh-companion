# Capability Router（能力路由）

把「我想做 X」翻译成「装哪个包」，并且明确说出代价。

## 何时用

- 「有没有插件能……」「想找个能做 X 的插件」
- 用户描述了一个需求，但没有点名任何插件
- 需要判断某能力是不是已经由已启用的模块覆盖

## 先排除三件事

1. **模型和现有工具能做的**：读写文件、跑命令、抓网页、生成 SVG/文档。这些不需要插件，别急着推荐。
2. **已启用模块能做的**：先查 `plugin_manager list_plugins`，200 个模块里常常已经有。
3. **只是界面/装饰需求**：那是主题或皮肤插件，属于另一条线，不要和能力插件混在一起。

## 流程

1. **拆能力**：把任务拆成动词短语，例如「语音输入」「会话检索」「Git 工作树」「共享会话」「桌面自动化」。一次任务通常 1–3 个能力。
2. **查索引**：读 `references/bundle-index.md`，按能力标签找候选。
3. **核实**：跑 `plugin_manager list_bundles`，确认 `availability`（installation / profile / missing）与 `enabled`。索引会过期，以实际返回为准。
4. **给建议**：包名 + 匹配理由 + 代价。
5. **停下**：只有用户明确说「装」才执行 `install_bundle`。

## 输出格式

| 能力 | 候选包 | 状态 | 代价 |
| --- | --- | --- | --- |

代价至少要写清四种：

- **实验性**：包名带 `experimental`，行为可能变。
- **下载**：首次使用要下运行时（如语音输入下载 SenseVoice）。
- **改动面**：会不会改 profile、影响其他会话。
- **重启**：装完是否需要重载宿主才生效。

## 边界

- 不自动安装、不自动启用、不替用户做「装哪个」的决定。
- 版本不兼容要提前说。反例：`@dsh-persona/workshop` 要求 `engines.dsh 0.2.1-rc.3`，当前运行时是 `0.2.2-rc.1`，直接装会报 `incompatible-version`。
- 插件解决不了就直说，别硬凑一个包。
- 推荐不等于验证：装了不等于跑通，能力仍需实测。
