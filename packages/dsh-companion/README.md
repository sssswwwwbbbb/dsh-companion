# DSH 陪伴 · Mac 完整流程验证版

当前包名为 `dsh-plugin-companion`，适配 Mac ARM64、DSH 0.2.1-rc.5。插件内自带桌面组件，所有安装后的操作都从 DSH 侧栏「陪伴」进入。

1. 在 DSH「添加插件」中输入发放者提供的 HTTPS `.tgz` 安装链接，安装源可选内置的中国大陆镜像。安装并启用后，在「陪伴」→「开始使用」→「统一授权」输入激活码，点击「激活本机」。启动动画和桌宠共用一份设备授权。
2. 选择配置包；配置同时影响启动动画、动作素材和相处节奏。示例中提供日间与月色两套配置，支持导入、导出 JSON 配置文件。
3. 使用插件创建的「DSH 陪伴启动器」打开 DSH：先显示原生启动动画，再打开官方 DSH，准备就绪后交给桌宠。直接打开官方 DSH 时，插件会在其加载后启动陪伴功能。
4. 在「桌宠控制」调整大小、行为和互动；在「授权与更新」刷新授权、解绑设备、检查更新并下载经过签名及摘要校验的私有安装包。

启动动画使用 DSH 窗口的尺寸与位置；DSH 尚未打开时使用上次记录，首次则使用居中的 DSH 默认窗口尺寸。窗口移动或缩放时会同步动画窗口。关闭「播放启动动画」会立即结束正在播放的动画。dev.11 区分正常启动与运行中启用：保持插件启用后重新打开官方 DSH，按设置自动播放开场；在运行中的 DSH 停用再启用插件，只恢复桌宠，不强制重播。陪伴启动器、手动重播和首次激活预览继续可用。

「授权与更新 → 插件 → 停用」使用 DSH 官方插件开关，停止桌宠和动画并移除启动入口，插件列表会显示停用。恢复时在插件列表重新启用即可保留原授权和配置。「启动入口」一行的「停用 / 启用」只管理启动器，不会改变插件启用状态。

从旧名 `@local/dsh-companion` 升级时，先在 DSH 卸载旧版，再安装本包。更新或重装时，按 DSH 的原生流程卸载旧包并安装下载文件，然后重新打开 DSH。授权和配置保存在独立目录并保留；停用、卸载时停止桌宠并移除启动入口，重新启用或安装后恢复。退出 DSH 时桌宠停止，启动入口保留供下次使用。

dev.8 起提供免登录的 HTTPS 在线安装入口，授权与适配更新继续使用独立 HTTPS 服务，并沿用 DSH 的官方代理路由。安装包仅包含公钥和服务地址，不包含签发私钥、管理员凭据或激活码。默认每份演示授权绑定一台设备，提供有限的离线续用期；具体有效期由发放者设置。从此前本机验证版升级时，需使用发放者提供的云端激活码。授权请求失败的本机诊断仅记录错误码和请求编号，不记录激活码、授权签名或硬件标识。

正式 Mac 签名公证、其他 DSH 版本、Windows 和长期稳定性仍需分别验收。当前使用本地开发签名，不改动官方 DSH 程序文件。示例素材按非商业自用范围使用，许可及署名保留在组件内的 ASSET-NOTICE.txt。

激活码的有效天数为 0 时，授权永久有效，插件显示“永久”。永久授权仍按约定的设备数和离线宽限运行，可以解绑、停用和恢复。永久授权需要本版或更新的插件；旧版有限期授权继续有效。

npm 发布准备已完成。正式发布前以发放者给出的 HTTPS 安装链接为准，尚未发布的包名不能用于 npm 在线安装。源码仓库与开源许可证后续另行公布。
