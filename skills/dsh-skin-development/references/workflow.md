# 开发与验收流程

这份流程用于范围确认后的实施。当前缺少首套皮肤范围，先填需求模板；清单确认后再按实际规模细化任务。

| 阶段 | 需要完成的内容 | 可检查的产物 |
|---|---|---|
| 范围讨论 | 定义皮肤的覆盖面、功能边界、首版取舍、角色风格、运行平台 | 范围表、功能清单、未定问题 |
| 能力核对 | 对照当前代码和目标版本的官方扩展点，确认哪些可配置、哪些需要新增适配 | 能力矩阵：已有 / 待扩展 / 未验证，附源码或文档证据 |
| 体验设计 | 统一颜色、背景、字体、图标、动效节奏和选中状态；只设计已选模块 | 关键界面、状态样例、模块关系、验收标准 |
| 素材准备 | 列出图片、动画、音频、字体及动作状态，检查尺寸、透明度、循环和许可 | 素材清单、来源、授权或许可证、资源预算 |
| 配置设计 | 确定皮肤 ID/版本、宿主适配范围、模块开关、资源引用和默认配置；兼容现有包 | 经审查的配置合同、迁移和回退规则 |
| 开发联调 | 先使一套最小皮肤贯通各选定模块，再完善状态、导入导出和错误恢复 | 可运行样例、实现与清单的对应关系 |
| 真实验收 | 在目标 DSH 和真实 Mac 桌面测试视觉、交互、生命周期、性能及异常 | 截图或录像、结构化报告、已过与未过项 |
| 打包交付 | 检查包内资源与私密文件、版本和摘要；执行本次已授权的分发步骤 | 安装地址或本地包、版本与摘要、使用步骤、适配说明 |

## 模块的设计要点

以下模块均为候选，只有需求清单选中的模块才进入实现。

- DSH 主界面：主题 token、背景层、侧栏、会话列表、消息、输入框、插件页、弹层；避免只给陪伴插件自身换色却宣称全局换肤。
- 角色与图标：提供缩放与透明背景要求，确认是否可修改品牌标识；保留必要的状态可读性。
- 启动动画：窗口范围、时长、跳过、冷启动/重播、DSH 就绪交接，窗口动画与桌面桌宠分别控制。
- 桌宠：复用现有动作映射与本地行为状态机，按角色动作清单补素材；检查透明边缘、方向、拖拽和多屏。
- 声音与交互：触发条件、开关、音量和静音体验需要明确；没有用户选择时不默认增加。
- 皮肤设置：一份配置关联选定模块，允许必要的模块开关；切换、重启和导入导出后的结果可复现。

## 素材清单应包含

资源 ID、用途/触发状态、格式与尺寸、透明度、帧率或时长、循环方式、体积、来源、许可/用户授权、署名要求和允许的分发范围。私有素材缺少的项目列为待准备，不编造权限；当前非商用示例素材不自动代表可商用。

## 需要验证的生命周期

- 未激活安装 → 激活 → 选皮肤 → 所选模块生效。
- 模块启用/停用、插件启用/停用、启动入口启用/停用三类状态分别正确。
- 移除启动入口 → 同处启用恢复；插件停用 → 官方列表重新启用恢复。
- 重启、换肤、重装后保留应保留的配置与授权；撤销皮肤后恢复原界面，不留下背景、样式、声音、窗口或监听器。
- 冷启动和已打开 DSH 时的重播都按窗口尺寸工作；窗口移动、缩放、显示器变化后无无效坐标。
- 授权服务临时不可用时遵守已签名的离线规则；失败有可追踪的错误码与请求编号，日志不包含密钥、完整激活码、授权签名或硬件标识。
- 在规定的缩放、明暗/对比度和所选交互场景中验证；记录实际包体积、进程数和资源占用。

自动测试覆盖配置边界与状态合同；真实 UI 和桌面行为用对应应用验证。避免只截图样机，或只完成打包就宣布整套皮肤验收通过。
