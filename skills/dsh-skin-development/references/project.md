# 当前项目与证据入口

项目目录：`<本机路径>`。项目当前没有 Git 仓库；不要替用户创建公开仓库或选择开源许可证。

产品从「启动动画 + 桌宠」扩展为「一整套 DSH 皮肤」。具体覆盖的界面与功能尚未确认，首套角色和美术主题也未确定。先在新对话讨论范围，不把候选模块全算进首版。

## 当前能力

- `packages/dsh-companion/`：DSH 插件、侧栏入口、配置包和授权客户端。
- `runtime-src/`：Mac Electron 桌宠、启动动画、桌面窗口和原生启动器。
- `packages/dsh-companion/src/packs.mjs` 与 `packs/*.json`：现有配置包合同。导入校验严格，扩展皮肤字段必须同步设计校验、存储、渲染、导入导出和兼容策略。
- `licensing/`：统一激活码、设备限制、永久授权及有限离线宽限；已有轻量管理后台。
- `designs/dsh-companion-v1/`：现有样机、角色素材和行为系统。样机不是全局主题的实现证据。
- 安装源为自有 HTTPS tgz；包名 `dsh-plugin-companion`，尚未发布公开 npm。
- 已验证目标为 Mac ARM64、DSH `0.2.1-rc.5`。后续以本机版本及最新验证记录为准。

## 接手时检查

1. 读取 `package.json`、`CHANGELOG.md` 和 `docs/first-skin-handoff.md`。
2. 读取最新的 `reports/dev11-summary.json`（若存在）、`reports/dev11-host.json`、`reports/online-install-summary.json`，区分本地实现、已分发版本和实机验收。未来升级时以报告内版本和实际安装版本为准。
3. 需求讨论阶段只读源代码与报告，不操作管理后台、不改用户真实 DSH 配置。
4. 接入全局皮肤前核对官方 DSH SDK 的样式、布局与客户端扩展接口。源码可从本机官方应用的 ASAR 通过其 Node 模式读取。

## 已知用户反馈

- 启动动画应匹配 DSH 窗口，不应默认铺满屏幕。
- 插件停用必须与 DSH 插件列表一致，并停止桌宠和动画。
- 启动入口移除后应能在同一处恢复，按钮文字只用「停用 / 启用」。
- 保持插件启用后重新打开官方 DSH，应按动画设置播放；只在运行中停用再启用插件时不强制重播。两条路径必须分别测试。
- 用户重视开源复用、轻量资源占用、简单的界面和正式流程闭环。

这些反馈属于宿主基础能力。新皮肤应复用已验收的修复，不在每套皮肤中重复开发宿主、授权或分发系统。
