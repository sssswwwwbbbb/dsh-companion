# 机械姬原生静音开场 · 冷启动顺序复验

**本地复验通过，交主控补审。** 只修冷启动的两个就绪信号可能先后到达的问题。使用同一皮肤 `commander-workspace-private 0.2.0`、同一原生影片和工作区客户端。Mac arm64、DSH 0.2.1-rc.5，私有插件与执行器 0.1.0-dev.11。此前的 [六条实测和冻结](dsh-commander-startup-2026-11-05.md) 已保留。

原生端保存当前代次、内容键对应的工作区提交回执；窗口尺寸和工作区回执到齐时消耗一次冷启动请求。停止、切换或过期代次会使旧回执失效。工作区提交后才重读原生状态，桥晚于首个页面探测时也能发出就绪信号。未加轮询、延时或重播机制。

| 验收路径 | 结果 |
| --- | --- |
| 工作区先、尺寸后 | 用受控页面确认驱动真实私有 Host 和原生窗口。已提交时无窗口尺寸、未播放、桌宠保持隐藏；通过既有窗口同步入口送入尺寸后只播放一次，真实 `media-ended` 后同一桌宠恢复可见。重复发送同一回执和尺寸没有重播。 |
| 尺寸先、工作区后 | 实际重启私有 Host，恢复原 DSH 会话后自动播放一次，52 个可见采样未发现桌宠与开场叠出。真实片尾回到同一会话及未发送草稿；启动偏好已恢复关闭。 |
| 手动预览与 Esc | 在同一个复验版桌面实点 **陪伴 → 本套设置 → 预览开场**，按 Esc 提前回到原输入焦点，桌宠正常返回。 |

复验沿用同一条测试 Session。此前现场曾将那段草稿提交为测试消息，返回本地 `NO_ADAPTER`；记录保留，复验前按上轮留存值恢复了原未发送文本。随后手动 Esc、真实冷启动播放中及结束后，都从实际输入框读回同一份草稿。
