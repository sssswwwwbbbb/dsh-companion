## 实现和验收保持适度

2026-11-03，用户要求主控避免过度防御性编程、钻牛角尖，并在发现子任务有同类倾向时及时提醒；随后明确要求写入项目记忆或验收技能。

- 按真实使用场景、已确认需求和当前阶段目标开发验收，不为假想风险层层增加机制。
- 修复已复现缺陷，完成必要兼容和关键启停检查；不把后续能力或低收益极端边界自动设为当前阻塞。
- 测试与改动相称；证据足够、必要检查通过后及时推进，不在没有新问题的情况下反复扩大验证。
- 主控对过度设计、重复实现、无必要扩大范围的子任务及时指出具体问题，要求回到当前交付目标。

本约定适用于底座、皮肤和主控验收；详细分工见 [并行开发约定](parallel-development-2026-11-03.md)。

## 设计技能分工（2026-11-04 用户更新）

用户已安装两套新技能，要求后续使用；旧的 baoyu-design 已删除，从后续工作流中移除。

- `impeccable`：管理界面、皮肤库、配置页等 UI/UX、操作流程、控件反馈及交互审查的主技能。按实际工作界面采用 Operate 流程。
- `design-taste-frontend`（Taste Skill）：辅助皮肤与主题的字体、配色、构图、角色元素呈现及前端视觉落地。它主要指导前端视觉，角色原画、表情/透明动作与开场成片另由素材制作工具及规范承担。处理应用界面时读取其 app-screen 分支，不机械套用营销页规则。
- 每项任务选对应主技能，跨领域时补充另一套相关参考，不叠加两套完整流程或重复验收。用户已定的风格、产品范围和当前阶段目标优先；已有关键稿与验收成果继续复用，不因换技能自动重画、换色或重开历史验收。
- 后续主控审核、底座界面实现与视觉制作均沿用本分工。技能的初始化/检查步骤在实际对应任务中执行，本次切换约定不触发全量界面改版。

2026-11-04 用户进一步明确：核心产品是整套主题，更偏二次元、立绘、科幻、赛博和动漫等方向，管理页是其中一个部分。每套主题的角色、世界观、界面、背景、开场、桌宠及可选人设/状态表达应保持一致。Taste 的通用审美偏好（例如限制渐变/发光、某些配色或插画横幅）不作为所有皮肤的引擎限制或统一否决标准；按用户选定的主题取舍。管理操作强调清楚顺手，主题内容允许符合角色世界的视觉表现。首套仍沿用档案暖白与鲸鱼娘既定方向。

用户随后要求从候选中按需选择、整合，不全部安装。本项目已在 `.agents/skills/` 安装 `ui-ux-pro-max`（科幻/赛博/HUD风格检索）和 `anime-character-director`（原创角色/立绘专项），与上述两套已有技能分工使用。Design-It因本轮重叠、Game Assets Enhancer因游戏场景和fal.ai付费依赖暂不安装。来源固定提交、适用范围和本地验证见[项目技能索引](../.agents/skills/README.md)。不因安装触发首套重制、付费服务或真实DSH更新。
