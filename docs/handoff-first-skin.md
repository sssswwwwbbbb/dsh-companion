## 已确认方向

- 首套参考为 `LeeRolling/dsh-boot-suite` 默认“档案暖白＋鲸鱼娘扫描睁眼”，固定参考提交见调研。链接显示文字与目标不同，以已核对的实际仓库为准。
- 首轮技术组合为主工作区主题＋现有桌宠。常用流程全覆盖是设计目标建议，具体元素按宿主能力列清单；不能把所有第三方页面和系统原生区域都承诺已覆盖。
- 用户明确要求首套沉淀视觉规范、关键界面及状态稿，并为后续皮肤积累可复用结构。主题色、字体、角色和具体动效仍属于各皮肤。
- 需要轻量“小巧思”，希望可配置；每套支持项带默认值，不支持项隐藏，关闭与不可用区分。模型切换/形象映射是例子，不直接把所有候选都做完。
- 不做外部壁纸/Wallpaper Engine 兼容，保留自带背景。不采用像素风；像素 UI 仅是实现参考。制作编辑器、上传和市场后置。

## 推进顺序与产物

按用户补充执行 [开源复用原则](parallel-development-2026-11-03.md)：配置界面、动画处理、素材检查及其他通用能力优先复用现有或合适的开源工具，不重复实现已有能力；记录实际采用内容的来源与版本，分别核对代码和素材的使用范围。

1. 在 `designs/dsh-skin-v1/` 建立首套设计工作目录，先形成简洁视觉规范：主/强调色职责、文字层级、材质、间距、组件状态和模式策略。
2. 制作可查看、可交互的关键稿，至少包括真实聊天结构的工作区、设置/菜单弹层，以及启动—工作区—桌宠的连贯对照。用本地模拟内容检查长回复、代码、表格、输入、滚动和小窗口；不是营销页面，也不把旧角色样机当本次定稿。
3. 配置页提供默认、已自定义、用户关闭、能力不可用等状态；不支持项隐藏，始终保留管理和停止/恢复入口。映射等复杂项使用适合的小编辑区。
4. 做角色/动作资源对照表及覆盖矩阵。核对扫描角色、背景与现有 Q 版桌宠是否可形成同一角色体验；记录画布、锚点、透明边缘、循环、缺失动作、来源及使用范围。
5. 从候选中选少量适合的互动编排具体时序，明确优先级、互斥、中断、回待机、冷却和减少动态方案。标为设计提案，不擅自扩大正式功能或让底座一次实现全部候选。
6. 持续读取共享合同，写 `integration-needs.md`，列出所需模块、参数、状态及资源；合同未就绪先完成风格、页面和素材工作，模拟行为明确标记。
7. 合同中相应能力定型后，形成包含声明、资源和默认配置的可加载皮肤内容，在本地/隔离联调中修正。若依赖未就绪，先完成所有独立产物并准确记录剩余接入项。

## 文件与素材职责

写入 `designs/dsh-skin-v1/`、`docs/first-skin-design/`、`reports/first-skin/`。共享合同由底座线维护，本线通过自己的 `integration-needs.md` 提出场景，不修改 `runtime-src/`、`packages/dsh-companion/`、底座或授权服务。

现有 `designs/dsh-companion-v1/` 是只读参考和技术素材来源，不覆盖它。上游视频/音频与代码许可不同，当前未知项如实列出；不能把扫描片自动当作桌宠动作包。缺资源可用明确占位继续验证界面，不虚构作者授权，不对外分发未确认素材。

允许本地设计产物、预览及必要的隔离检查；不安装到用户真实 DSH、不修改其 profile、不部署或发布。共享工作目录下不自行 commit/merge/push，不操作公共暂存区。
