# DSH 皮肤制作手册

> 2026-11-08 最新版开发说明与素材清单见 [主题盒子 1.0 交接包](skin-kit-v1/README.md)。下文保留旧制作记录，版本与能力以最新版为准。


2026-11-06。首套「冷启动」0.4.0 已获用户验收，角色为「单元-07 / CS-07」。本手册把首套的制作方法、当前能用的包接口和下一套的验收口径整理到一起。接口以已交付的 dev.26 安装包为基准，目标平台为 Apple 芯片 Mac。dev.27 扩展到 DSH 0.2.2-rc.1，沿用该皮肤包接口。DSH 版本兼容须按交付包逐个验证。[首套验收入口](first-skin-design/CURRENT.md) · [dev.27 兼容修复](dsh-cold-start-dev27-2026-11-06.md)

## 1. 先选制作路径

目标是让主题、角色、开场和桌面陪伴在一个工作场景里互相呼应。能用现有模块表达的效果，制作方交 `skin.json`、素材和验收说明即可。新能力由引擎适配后再开放给皮肤。

| 路径 | 适合的需求 | 实际交付 |
| --- | --- | --- |
| 基础数据包 | 换明暗配色、静态背景，或者添加现有播放器支持的开场及桌宠动作 | 单个本地皮肤 ZIP，在「陪伴 → 皮肤库」导入 |
| 沿用现有预设 | 用已有工作区结构表达新主题，换配色、语义图标和角色素材 | ZIP 加真实 DSH 回归。预设的具体覆盖面和当前 UI 是否展示对应配置都要实测 |
| 引擎集成 | 自定义工作区布局、专属控制面板或封面、精确透明命中、连续走路和转正、新事件或新控件 | 皮肤内容加受审的引擎适配，再发插件安装包；必要时同时交 ZIP |
| 后续创作者工具 | 插件内自制、预览、导出、上传，外部作者可用开源工具制作 | 已列入路线图。本地 ZIP 导入已经有，制作器、上传和公开分发服务仍待实现 |

「冷启动」走第三条。基础颜色、角色素材、动作和开场都在皮肤清单里。紧凑角色条、皮肤库专用卡片、高清桌宠几何、左走后原地转正和低占用待机分别依赖预设或原生适配。新 ZIP 写入同样字段可以复用已有预设支持的部分，`commander-v1` 这个名字也不自动赋予新包首套的专用卡片或桌面后端。

开始前用一页任务单定好主题名、皮肤 ID、角色名和型号、用户称呼、工作场景、必做模块、可选互动、目标 DSH 版本、素材权属和出包路径。每个必做效果写一句可以当场验证的描述，例如「调大角色后在当前位置变大，继续能点按，DSH 不出现启动进度」。能明确哪些能力确实缺失后，再安排引擎改动。

## 2. 从立项到交付

| 顺序 | 谁负责 | 做什么 | 交审产物 |
| --- | --- | --- | --- |
| 1. 定场景 | 产品、设计 | 写出使用者是谁、角色是谁，以及打开应用、专注工作、完成任务三个场景中角色做什么 | 一页主题任务单，区分必做、可选、后续 |
| 2. 对接口 | 引擎、设计 | 用下文的表逐项匹配配置。挑出一个最能暴露接入难度的效果做最小验证 | 功能、声明字段、素材和宿主版本的对应表 |
| 3. 冻结母版 | 角色、美术 | 选定角色正面及标志性元素，定明暗配色、图标语言、音色和转场节奏 | 角色设定板、色板、图标规范、声音方向及已选参考 |
| 4. 做关键稿 | UI、动效 | 在真实工作区的比例上做默认、运行、完成、待处理。同步画开场分镜和角色待机、回应 | 明暗工作区、设置页、开场首尾、待机与回应对照 |
| 5. 出最小实装 | 引擎、设计 | 用少量正式素材贯通导入、应用、预览、原入口冷启动和退出恢复，先验证目录可用、角色高度和清晰度 | 可安装的小包、实机截图和当轮问题 |
| 6. 补齐正式素材 | 美术、音频 | 依照已通过的尺寸、锚点和表现补完状态，导出运行文件、检查许可 | 素材清单、源文件、编码导出、声音轨及许可台账 |
| 7. 冻结与回归 | 引擎、主控 | 冻结素材及 SHA-256，验证包、目标 DSH 和既有用户数据，实际运行冷启动、换肤、配置和回退 | ZIP 或插件 tgz、包摘要、版本范围、结果和已知边界 |
| 8. 用户验收 | 用户、主控 | 从日常入口按任务单亲自操作，区分主控实机验证和用户验收 | 用户结论、实际使用版本、后续问题 |

配色与角色制作可以和引擎接缝验证并行。共用同一份角色母版、资源 ID 和验收清单。每个节点交一个冻结版本，带上它的差异和需要主控确认的范围。对实际工作场景做必要的回归，证据充足后进入下一阶段。

设计工具按需选用。设置页和皮肤库的操作体验用 `impeccable`。主题视觉使用 `design-taste-frontend` 或项目内 `ui-ux-pro-max` 的相关风格参考。原创立绘可用 `anime-character-director` 组织角色约束。PixelFX、Scenario、MOSS 和即梦属于素材生产参考，采用前核对所用许可、实际工具权限与输出质量。[项目技能索引](../.agents/skills/README.md) · [素材参考库](first-skin-design/material-library.md)

## 3. 设计交接和素材清单

### 角色母版

- 定下全身正面原图，条件允许时补侧面、背面、局部近景及关键表情。整套共用固定的发色、瞳色、轮廓、发饰、衣装、鞋型和身份标识。源稿保留足够像素，人物全身入画，避免预先裁掉头饰和鞋尖。
- 开场关键帧、工作区头像、皮肤封面、桌宠透明动作使用同一组身份锚点。动效分镜标出起止姿态、镜头、声音节点以及工作区交接。前后两帧应能作为静态稿单独审查。
- 做一张同尺寸对照板，把开场关键帧、工作区小头像、桌宠站姿和动作中间帧放在一起。在真实显示尺寸看人物辨识度、边缘、光线和比例。
- 保留源稿与派生关系。记录参考、工具或模型快照、人工修订、作者和授权。运行包只放本次用到并有权交付的成品，源稿和制作凭据单独保存。

### 按功能准备成品

表内像素和秒数是制作参考。技术限制以第四节的清单校验为准。

| 资源 | 哪些场景需要 | 建议和首套参考 |
| --- | --- | --- |
| 明暗配色表 | 主题模块必需 | 同时交正文、弱文字、底色、表面、边框、选中、警告、错误和成功色，逐一对应允许的主题 token |
| 工作区静态背景 | 需要背景时 | PNG、JPEG 或 WebP。建议有留白，长代码和表格上保持可读。首套清单有 1440×900 背景资产，是否显示由对应字段或预设决定 |
| 入口标识 | 想换陪伴入口图标时 | 明暗各一枚 PNG，检验小尺寸轮廓和选中状态 |
| 语义图标 | 使用预设替换具体图标时 | 明暗两套透明 PNG，保证线条粗细、视框和光学居中一致。首套 56 个语义位，每个浅深两张，通常为 96×96 |
| 角色封面 | 设计交付和皮肤宣传 | 首套为 960×600 PNG。dev.26 通用清单没有独立的 `cover` 字段，皮肤库的定制封面需要客户端支持 |
| 工作区头像、肖像、全身静帧 | 声明 `theme.workspaceRole` 时 | 三张 PNG。首套分别为 256×256、384×432、499×1024。小头像优先让眼睛、头饰和轮廓清楚，侧栏只占紧凑一行 |
| 工作区角色待机和回应 | 声明 `theme.workspaceRole` 时 | 两段 WebM，首套为 499×1024。通用清单要求这两个引用齐全，具体预设可以只显示静态头像 |
| 桌宠待机 | 自定义桌宠媒体必需 | 一段有真实 Alpha 的 WebM。起始帧要适合长时间静置，循环则首尾姿态、脚点和亮度连续 |
| 桌宠回应 | 建议作为第二段 | 一段透明 WebM，建议先做约 1–2 秒可识别动作，片尾平稳回到待机。首套为 1.5 秒 |
| 走路、跑动和转正 | 只做已选动作 | 交素材原步态、地面基准、方向、起停和动作位移预期。首套左走与转正分片，由原生适配控制窗口移动。未准备好的方向先不开放 |
| 桌宠命中数据 | 精确原生桌宠路径需要 | 交画布尺寸、人物 Alpha 轮廓、透明穿透测试点、角色脚点、各动作对齐参数。由引擎生成或校验使用的命中数据 |
| 开场静帧 | 声明任何 `startup` 都需要 | 使用能独立表达开场的静态图。首套 1280×720 PNG，和影片内容同源 |
| 开场成片 | 动态开场 | WebM 或符合 v3 条件的 MP4。有声 MP4 以 H.264、AAC、快速起播导出为制作建议，实际在目标 DSH 解码。首套 1280×720、12.5 秒 |
| 配音、音效和混音源 | 需要声音时 | 分轨交配音、环境、音效及成片，记录声音来源、许可和时间点。运行时使用已混进开场影片的音轨 |
| 道具与局部特效 | 已有匹配动作和接入时 | 交透明图或逐帧源，标明抓握点、接触面、遮挡和出现/收起帧。书杯等道具应在角色实际使用时出现 |
| 短句与角色语气 | 主题文案、状态或桌宠互动 | 交角色名、称呼、就绪/回应等文案。为静音、离线或无模型情况提供可用的文本或动作 |

### 导出检查

- 透明媒体在黑底、白底和实际桌面都看一遍。确认是真 Alpha，排除烘焙棋盘格、黑边、亮边、飞散像素和转场残影。视频工具需要用能读到 Alpha 的解码链抽帧，实际 DSH 窗口也要显示正确。
- 记录人物有效像素高度和目标屏幕密度。首套运行派生使用 1920×1080 带 Alpha 的桌宠 WebM，逻辑画布仍为 640×360。缩小文件时优先减少无意义动作、裁掉无用空白和压缩素材，先用同尺寸截图比较人物清晰度。
- 台词与最后一帧对齐，静音下依然看得懂。测试音量、启停、按 Esc 后停音和回到同一工作区。声音开关控制成片音轨。动画以真实片尾结束，静帧另用单独时长。
- 所有文件导出完成后再计算字节数和 SHA-256。文件发生任何替换都更新对应声明，并重跑真实播放、脚点和命中检查。文档记实际测得的尺寸、帧率、帧数和时长。

每条素材建议在制作台账保留这些列。

| 资源 ID | 场景及触发 | 源稿/作者 | 成品路径 | 格式/尺寸/Alpha | 时长/帧率/循环 | 锚点 | 字节/SHA-256 | 许可/署名/分发范围 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `master-react` | 桌宠回应，结束回待机 | 已选角色母版和动作源 | `assets/master-react.webm` | WebM / 1920×1080 / Alpha | 1.5 秒 / 24 fps / 单次 | 地面点和首尾同待机对齐 | 以导出文件为准 | 按该文件原始记录填写 |

## 4. 皮肤作者接口

### 包根和基础清单

皮肤包是 ZIP，`skin.json` 直接放在 ZIP 根。资源以相对路径列在 `assets` 下，模块通过资源 ID 引用。设计稿、工程源文件、独立许可证和交付台账可作为作者项目随附材料。导入器只把清单和声明的资源写入皮肤快照。

| 顶层字段 | 规则 |
| --- | --- |
| `formatVersion` | 当前固定为 `2` |
| `id` | 3–64 个字符，小写字母开头，后续允许小写字母、数字和连字符。同一套迭代沿用 ID |
| `version` | `X.Y.Z`。准备更新时升版本，名称相同的历史版本可以并存 |
| `name` / `description` | 名称必填且不超过 80 字符，描述可选且不超过 500 字符 |
| `dshVersions` | 1–10 个准确的目标 DSH 版本。作者依据自己的实测填写，预发行版本也写全，例如 `0.2.1-rc.5` |
| `assets` | 资源 ID 映射。可为空，最多 128 项 |
| `modules` | 至少一个模块。当前已知执行模块为 `theme`、`pet`、`startup` |

每个模块含 `interfaceVersion`、`configVersion`、`required`、`config`、`settings` 五项。当前三模块的 `interfaceVersion` 都是 1。`required: true` 表示缺能力或应用失败时整套应用不能提交，`false` 表示可选效果，界面会记录模块结果。

`config` 放固定值和交付素材引用。`settings` 声明给用户调的已支持字段，每项要有 `label` 和合法 `default`。同一字段选一个位置。可选的 `showWhen` 使用同模块已声明的布尔或枚举字段，依 `{ "field": "...", "equals": ... }` 判断。引擎按自身缺省、皮肤值、用户覆写的顺序取有效值。皮肤未开放的配置不出现在可配置项里。当前设置页主要按已知模块和字段布局，设计新控件时实测展示，字段进入 schema 并不自动得到完整的产品入口。

### 资源条目

| 字段 | 规则 |
| --- | --- |
| `path` | 包内相对路径，最多 240 字符。建议用小写英文和连字符，允许数字、下划线、点和空格。路径里不能有空段、`.`、`..`、绝对路径或链接 |
| `mime` | PNG、JPEG、WebP、WebM。MP4 仅限 `startup` 接口 1、配置 3 里被 `config.video` 引用的资源 |
| `bytes` / `sha256` | 文件精确字节数和 64 位小写十六进制摘要。引擎还检查文件头 |
| `width` / `height` / `alpha` | 可选声明，建议给齐。尺寸是 1–8192 的整数，Alpha 为布尔值。媒体实际解码仍需独立核对 |
| `source` / `license` | 可选字段，建议逐件填写，每项最多 1000 字符。复杂条款和署名另存作者台账 |

清单最多 64 KiB，图片每件最多 8 MiB，视频每件最多 16 MiB，声明资源合计最多 128 MiB。ZIP 本身最多 129 MiB，最多 256 条归档记录，解包总量最多 128 MiB 加 64 KiB。首套 128 项已经达到资源数量上限，后续优先按实际使用的语义位导出，源文件留在作者项目。

### `theme` 工作区主题

| 配置版本 | 需要实现 | 可选项与配套素材 |
| --- | --- | --- |
| 1 | `config.tokens` 必填。每个允许的 DSH 语义 token 提供 `light` 和 `dark` 两个色值，支持 `#RRGGBB` 或 `#RRGGBBAA` | `background` 指向静态图片。可开放 `backgroundOpacity`，范围 0–0.15 |
| 2 | 继承 v1 | `entryMarks` 明暗 PNG 与 `entryMarkEnabled` 配套。可选 `workFeedbackEnabled`、`petEchoEnabled` |
| 3 | 继承 v2 | 工作区细节需成组提供 `workspacePreset`、`semanticIcons` 和 `workspaceDetailsEnabled`。预设枚举为 `archive-warm-r2` 与 `commander-v1`，可选 `workspaceMotionEnabled` 和 `workspaceRole` |

`semanticIcons` 把语义 ID 映射到 `{ "light": "资源ID", "dark": "资源ID" }`，每个版本最多 64 组。只配置已被适配器消费的语义位。`workspaceRole` 要完整提供 `poster`、`portrait`、`avatar`、`idle`、`react`，也可成对加 `name` 与 `model`。型号只用大写字母、数字和分隔连字符，例如 `CS-07`。`petEchoEnabled` 同时依赖工作反馈字段以及桌宠 `idle`、`react` 动作。

工作反馈沿用 DSH 会话状态，覆盖待机、执行、待处理、完成。完成动作按原逻辑去重，用户输入、切换会话或停止应能打断装饰反馈。首套验证了紧凑角色条和工作区真实操作。对字体、原生标题栏、插件页、弹窗、模型选择器等要逐面核对实际覆盖。任意字体文件、CSS/JS、第三方壁纸工程和自定义布局目前没有通用数据入口。[主题令牌表](../packages/dsh-skin-core/src/theme-tokens.json) · [工作区接口与证据](skin-workspace-v2-interface-2026-11-04.md)

### 工作区回复风格

主题盒子 dev.35 起，皮肤可在根 `skin.json` 声明可选的 `replyStyle`。填写默认称呼与语气，称呼最多 32 字符，可填空字符串。语气为 1–280 字符，描述表达方式、详略与先后顺序。

```json
"replyStyle": {
  "address": "指挥官",
  "tone": "语气冷静、简练。先给结论，再说明依据或下一步。"
}
```

在「本套设置」编辑并保存。用户在会话标题旁主动开启，新会话默认为关闭。切到其他皮肤或停止效果后，本皮肤的风格撤下。桌宠仍使用自己的 `pet.persona`，作者可分别提供两个场景的文案。含此字段的皮肤要求主题盒子 dev.35 或更新版本。

### `pet` 桌面陪伴

| 项目 | 声明及行为 |
| --- | --- |
| 基础动作来源 | `config.builtinPack` 必填且须存在于插件。可查已打包的 `packs/`，首套使用 `whale-maid-demo`。声明自定义动作时用本套资产 |
| v1 和 v2 的差异 | v1 可沿用内置动作，若声明 `animations` 则要覆盖 12 槽。v2 须声明 `animations`，支持从只有 `idle` 开始的真实子集 |
| 动作字段 | 每项含 `asset`、`seconds`、`loop`，时长范围 0.1–60 秒，引用 WebM。可用槽位为 `idle`、`look`、`walk`、`run`、`stretch`、`eat`、`play`、`greet`、`react`、`sleep-in`、`sleep`、`wake` |
| 大小与位置 | `canvasHeight` 100–400，`canvasOffsetY` −40 到 40，`size` 70%–140%。前两项用于角色拟合，`size` 可开放给用户 |
| 本地行为 | `profile` 可用 `free`、`gentle`、`lively`。可选 `autonomous` 和 `followMouse`。v2 不足全套动作时不能开启或公开自主行为，缺少 `walk` 时不能开启或公开跟鼠标 |
| 轻量互动 | `actionDescriptions` 只描述实际可用动作，每条最多 120 字符。模型动作不开放 `walk` 和 `run`。可填 `localReply`，最多 120 字符 |
| 智能互动 | `smartEnabled`、`persona`、`modelSelection`、`historyRounds`、`allowSpeech`、`allowActions`。人设最多 2000 字符，记忆轮次 0–20，本次运行有效。模型可跟随当前，也可填 `{ "mode": "specific", "provider": "...", "model": "..." }` |

`persona` 和动作描述要配齐才有对应的桌宠互动声明。点击或桌宠专属输入进入既有本地/模型决策，实际动作取运行可用子集。`allowSpeech` 控制互动短句，开场音轨另有设置。桌宠人设由皮肤声明，作用域为桌宠互动。工作区 Agent 与桌宠共用人设、切换模型时播放动作或换形象均属于后续可选能力，新增前先核对触发点、配置默认值和宿主权限。

首套原生后端把已审的精确内容 key 和原生几何绑定，开发输入包括透明轮廓、脚点、逻辑画布、缩放基准、动作媒体与摘要、方向、步幅和转正片段。仅改 ZIP 内容会产生新 key，需要在集成路径重新匹配并验收。基础自定义动作仍有现有通用路径。使用现有 `dsh-pet` 更新窗体尺寸与命中通路，角色缩放应原地生效。高清停帧待机属于已验收首套的运行策略。[桌宠动作接口](skin-foundation/pet-animation-subset-contract-m4.md) · [几何与命中](dsh-pet-geometry-2026-11-04.md) · [走路与转正](dsh-walk-native-2026-11-05.md)

### `startup` 开场

| 配置版本 | 要实现的字段 |
| --- | --- |
| 1 | `poster`、`seconds`、`greeting`、`subtitle` 必填。可加 WebM `video`。静帧开场可参考已有样例 |
| 2 | 动态影片必需，并声明 `handoffSeconds` 和 `stillSeconds`。可公开 `reducedMotion` |
| 3 | 延续 v2，影片可用 WebM 或符合规则的 MP4，可公开 `soundEnabled` |

`seconds` 为 1–15 秒，和实际影片时长对齐。`handoffSeconds` 为 0.1–1 秒，须短于影片。`stillSeconds` 为 1–15 秒，且不长于影片。`greeting` 最多 100 字符，`subtitle` 最多 180 字符。首套使用 12.5 秒正片、0.35 秒交接和 1.2 秒静帧。正常流程是完全退出 DSH 后点原图标，在原 DSH 窗口进入开场，片尾交接到当前工作区；Esc、进入工作区按钮、关闭自动开场以及减少动态均需验收。切换皮肤、改开场参数和热启停时检查工作区连续性。开场自动播放是插件全局偏好，声音和减少动态可以是本套偏好。[静帧样例](../packages/dsh-skin-core/examples/startup-poster/skin.json) · [原入口开场实现与验证](dsh-cold-start-dev26-2026-11-05.md)

## 5. 最小示例与本地打包

先做一套只有配色的包，把安装到应用的路径跑通。在你的作者目录建立以下 `skin.json`。宿主版本用你实际测过的版本替换。

```json
{
  "formatVersion": 2,
  "id": "night-observatory",
  "version": "0.1.0",
  "name": "夜间观测站",
  "dshVersions": ["0.2.1-rc.5"],
  "assets": {},
  "modules": {
    "theme": {
      "interfaceVersion": 1,
      "configVersion": 1,
      "required": true,
      "config": {
        "tokens": {
          "--dsw-alias-bg-base": { "light": "#edf0f4", "dark": "#111a2a" },
          "--dsw-alias-label-primary": { "light": "#17293b", "dark": "#e5edf7" }
        }
      },
      "settings": {}
    }
  }
}
```

实际三模块皮肤在此基础上添加需要的 `assets` 条目，再添加对应模块。对照下例的结构，资源 ID 和时长以你的文件为准。

```json
{
  "pet": {
    "interfaceVersion": 1,
    "configVersion": 2,
    "required": false,
    "config": {
      "builtinPack": "whale-maid-demo",
      "canvasHeight": 195,
      "animations": {
        "idle": { "asset": "role-idle", "seconds": 2.5, "loop": true },
        "react": { "asset": "role-react", "seconds": 1.5, "loop": false }
      }
    },
    "settings": {
      "size": { "label": "角色大小", "default": 100 }
    }
  },
  "startup": {
    "interfaceVersion": 1,
    "configVersion": 3,
    "required": false,
    "config": {
      "poster": "opening-still",
      "video": "opening-film",
      "seconds": 12.5,
      "handoffSeconds": 0.35,
      "stillSeconds": 1.2,
      "greeting": "观测站已就绪",
      "subtitle": "可以开始今天的工作。"
    },
    "settings": {
      "soundEnabled": { "label": "开场声音", "default": false },
      "reducedMotion": { "label": "减少开场动态", "default": false }
    }
  }
}
```

这段 JSON 是合入 `modules` 的片段。向顶层 `assets` 增加 `role-idle`、`role-react`、`opening-still` 和 `opening-film` 的真实成品条目。开场引用 MP4 时保留配置版本 3。为单个文件取元数据可用下面两个命令。

```sh
wc -c < assets/role-idle.webm
shasum -a 256 assets/role-idle.webm
```

用目标安装包里的校验代码检查真实目录。下面从项目根执行，`skin_dir` 替换成你的目录。它读已发布到本机的引擎代码，校验清单、资源文件和设置默认值。

```sh
skin_dir="$PWD/designs/night-observatory/content"
plugin="$PWD/dist/dsh-plugin-companion-0.1.0-dev.26.tgz"
schema_dir="$(mktemp -d)"
tar -xzf "$plugin" -C "$schema_dir" package/skin-core/src
node --input-type=module - "$schema_dir" "$skin_dir" <<'JS'
import {pathToFileURL} from 'node:url';
import path from 'node:path';

const [engine, skinDir] = process.argv.slice(2);
const moduleUrl = pathToFileURL(path.join(engine, 'package/skin-core/src/index.mjs'));
const {loadSkin, prepareResources, resolveSettings} = await import(moduleUrl);
const skin = loadSkin(skinDir);
const assets = prepareResources(skin);
const modules = resolveSettings(skin.manifest, {}, {theme: true, pet: true, startup: true});
console.log(JSON.stringify({
  id: skin.manifest.id,
  contentKey: skin.contentKey,
  resources: Object.keys(assets).length,
  modules: Object.keys(modules),
}, null, 2));
JS
```

打包时只将清单和声明资源写进 ZIP。下面的脚本用 Python 标准库，保留清单和成品字节。输出文件写在皮肤目录外。

```sh
zip_path="$PWD/night-observatory-0.1.0.zip"
python3 - "$skin_dir" "$zip_path" <<'PY'
import json
import sys
from pathlib import Path
from zipfile import ZIP_DEFLATED, ZipFile

root = Path(sys.argv[1]).resolve()
manifest = json.loads((root / "skin.json").read_text(encoding="utf-8"))
paths = dict.fromkeys(["skin.json", *(asset["path"] for asset in manifest["assets"].values())])
with ZipFile(sys.argv[2], "x", compression=ZIP_DEFLATED) as archive:
    for relative in paths:
        archive.write(root / relative, relative)
PY
unzip -t "$zip_path"
shasum -a 256 "$zip_path"
```

1. 在目标 DSH 里先启用并授权「DSH 陪伴」插件。
2. 到「陪伴 → 皮肤库 → 安装本地皮肤」，选刚生成的 ZIP。导入后先入库。
3. 点击卡片应用，在「本套设置」核对默认值。两套来回切，确认设置按各自 ID 保存。
4. 调整成品后重新导出并升版本。ZIP SHA-256 用来识别具体交付文件，`contentKey` 由解析后的清单算出，用来识别运行快照。资源字节的变化应同步更新清单摘要，因此也会产生新内容 key。
5. 已发布皮肤更新时沿用稳定 ID，保留旧值的语义。若缩窄范围或换掉字段类型，先验证已存覆写会如何处理，再决定迁移或新 ID。

皮肤 ZIP 通过陪伴皮肤库安装。引擎改动、新运行适配或内置皮肤变更时，需要生成插件 `.tgz`，通过 DSH 的插件管理器安装。首套插件的可复现构建依赖冻结输入，具体见交付说明和构建入口。[首套打包说明](dsh-cold-start-dev27-2026-11-06.md) · [冻结构建入口](../experiments/dsh-cold-start-install/stage.mjs)

## 6. 新功能接入时引擎要交什么

制作方交设计、素材和配置示例。引擎方只为现有接口表达不了的需求补一条能力。优先核对 DSH 官方扩展点和 `dsh-pet` 已有入口，能复用已有事件、设置和生命周期就用现成的。

1. **配置合同**。定模块和字段、类型、默认值、范围、是否公开、显示条件、素材引用和能力不可用时的行为。明确现有包和已有覆写的处理。
2. **执行位置**。页面主题走 DSH 工作区适配，原生桌宠走桌面执行层，启动播放走原 DSH 启动页。皮肤配置提供数据，引擎拥有执行逻辑、授权和清理。
3. **模块生命周期**。由协调器复用 `available`、`prepare`、`apply`、`exit`。支持就地更新的字段可加 `supportsUpdate`、`prepareUpdate` 和 `update`。准备检查能力和资源，应用确认真实就绪，退出清理样式、监听、媒体和原生窗口。操作回执关联当前代次和内容 key，失败保留可恢复的选择。
4. **插件入口**。皮肤作者直接操作配置与包。设置页内部使用现有 `skinInstall`、`skinSelect`、`skinConfigure`、`skinDisable`、`skinReset`、`skinStop` 等操作。需要新行为时在引擎受控入口实现，作者不调用原生桥。
5. **实机样例**。用一个最小正常案例和一个关闭或能力缺失案例证明路径可用，再补正式素材。新动作若涉及窗口移动，验收方向、步幅、站定、转身、命中与回到待机。新设置若涉及缩放，验收同窗、同进程、位置稳定和正确的命中区域。

| 新想法 | 先交什么 | 引擎什么时候需要改 |
| --- | --- | --- |
| 点击角色做一次回应 | 真实回应媒体、静音文案、默认开关 | 已有触发、动作和配置都能覆盖时只做皮肤 |
| 工作完成时出现状态或动作 | 对应状态稿、开始/结束行为、默认和降级 | 超出已有工作反馈状态或需要新动作编排时 |
| 切模型时换形象 | 模型 ID、形象映射、默认形象、转场和测试样例 | 先接入模型切换事件和声明合同，处理同名模型、缺素材、快速切换 |
| 工作区和桌宠共享人设 | 一份公共角色设定，分别写两个作用域、默认开关和退出行为 | 先明确宿主允许的注入点、作用域与授权，再提供可选配置 |
| 新道具、攀爬或走跑 | 姿态、接触点、遮挡、动作时序和真实导出 | 现有桌面动作层无法安全消费时，加最小场景适配 |
| 新版 DSH 适配 | 目标 DSH 版本、失败截图、上一版能用的工作流 | 同时核对插件版本声明、皮肤兼容、宿主 API、原生桥和启动页，再用真实客户端回归 |

### 宿主升级的处理

先在目标 DSH 复现旧包。检查插件 `engines.dsh`、Host peer 依赖、插件和原生服务的兼容列表、皮肤的 `dshVersions`、原入口开场及工作区扩展点。给验证过的宿主精确列版本。保持冻结皮肤内容和用户选择可恢复。新增兼容策略涉及内容标识时，要检查旧选择、回退和原生资源映射。复用隔离官方 Host，依次验证真实包安装、实际主窗口、开场、桌宠和设置，再考虑日用升级。

## 7. 实机验收表

| 范围 | 必测动作 | 通过条件 |
| --- | --- | --- |
| 交付物 | 核对清单、资源字节和摘要，检查压缩包根、版本、许可 | 实际包和记录一致，源码资源台账可追溯 |
| 真实安装 | 用目标版本官方管理器安装、启用、授权，皮肤库导入并应用 | 页面、原生运行时和模块结果一致，旧选择和偏好按预期保留 |
| 主题视觉 | 明暗各看侧栏、目录、会话、正文、代码、表格、输入、弹层和设置 | 可读、可用。选中、悬浮和待处理提示清楚，角色位置给目录让空间 |
| 启动 | 完全退出后点原 DSH 图标，测试自然片尾、Esc、静音、减少动态和关闭自动播放 | 同窗开场在首次工作区可操作前出现。正常片尾按媒体结束交接，跳过无残音，原会话能继续 |
| 工作中 | 切换皮肤、反复改常用设置、停用再启用 | 当次工作区不被启动进度或开场打断。无重叠窗口和残留效果 |
| 桌宠 | 待机、回应、走路和收步，实点身体、拖动、透明区穿透 | 缩放前后等比，位置和命中准确。调大小无需重启。只有实际提供的动作可以触发 |
| 性能 | 同机比较空闲和互动，分别看桌宠进程组、媒体与系统并发负载 | 记录实际采样条件和占用。首套同机隔离待机的 CPU 数据仅作参考 |
| 恢复 | 关闭单模块、停止全部、恢复、重启、换回旧套 | 效果干净退出，设置和授权按合同保留，兼容或资源失败有可识别原因 |
| 用户验收 | 按用户原来的入口和工作习惯亲自操作 | 记录用户结论、适用版本和实测范围，和自动化或隔离结论分开 |

常见问题可从错误码定位。媒体尺寸或哈希不符查成品和清单，`SKIN_RESOURCE_MISSING` 查资源 ID 和 MIME。版本不匹配先查插件级安装门槛，再查皮肤级支持。遇到「安装成功但没换肤」，先确认插件已启用、授权有效、皮肤已从库里选择且所选模块实际就绪。出现开场晚弹、提前退场、调大小重建等问题时先保留真实日志和实际操作序列，分别验证启动、播放器和桌宠进程。

## 8. 对外创作的路线

目前开发者已能按这份合同用本地文件制作 ZIP，再通过插件导入。后续路线图保留开源制作能力，以及普通用户安装插件后自制、导出和上传皮肤。建议先把可公开的清单、样例、校验和打包入口形成最小创作工具，再在插件里接入新建、替换素材、配置默认值、预览和打包。上传接收位置、可见范围、作品审核、版本更新及许可约定另行明确。公开样例应使用有权再分发的素材。[创作者功能清单](first-skin-brief.md) · [首套素材生产记录](first-skin-design/material-library.md)
