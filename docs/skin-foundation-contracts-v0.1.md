# DSH 皮肤底座设计约定 v0.1

日期：2026-11-03（Asia/Shanghai）。状态：评审建议已获用户同意，本版完成五份设计输入；首轮技术验证组合已选定，具体元素、宿主能力和运行指标尚待核对。

本轮交付文档。协议名称和状态用于指导后续设计，不表示现有代码已经实现，不写入用户配置，也不执行实机操作。

相关文档：[整体方案](first-skin-brief.md)、[三角色评审](skin-plan-review-2026-11-03.md)、[评审时方案快照](skin-plan-reviewed-baseline-2026-11-03.md)。

## 已确认的推进方式与尚未冻结的选择

- 用户已同意先补齐最小体验、执行位置、切换状态、设置与版本、样例验收五份约定，再推进底座。

## 约定一：最小体验清单

### 目标场景（建议）

目标用户为已经使用 DSH 的 Mac ARM 用户，日常阅读回复、编辑输入并查看代码。希望换肤后主工作区具有统一视觉，仍能顺畅工作，并能理解应用、设置和退出的结果。

用户已确认的两个技术验证位置，具体变化按以下草案核对：

| 位置 | 最小变化 | 验证目的 | 需求状态 |
|---|---|---|---|
| DSH 主工作区 | 侧栏/会话区、聊天与输入区域中约定元素的配色和表面样式 | 验证宿主接入、日常可用性及完整撤销 | 已确认的技术范围；具体元素经接口核对后列清单 |
| 现有系统桌宠 | 沿用现有动作资源与本地行为，验证按包加载及设置协调 | 暴露页面与原生运行层的状态、资源和清理边界 | 已确认的技术范围；不确定首套角色，也不新增互动 |

现有启动动画与启动入口继续遵循原对话已验证的规则。正常换肤不自动重播开场；正式皮肤是否包括启动模块另行确定。

### 最短使用流程

安装并完成统一激活 → 查看皮肤会改变的效果及兼容情况 → 应用 A → 调整一个参数或关闭一个效果 → 应用 B → 返回 A → 退出皮肤效果。

在选择前显示名称、包含效果、当前可用/不可用项及是否需要重启。应用后的主结果用普通语言说明成功、因用户设置关闭、部分效果不可用或失败，并给出下一步；技术模块状态放详情中。

### 最小体验的通过条件

- 约定位置确实出现可见变化，切换后能识别当前使用的是 A 还是 B。
- 已选覆盖区域的长中文、代码块、表格、输入编辑、滚动与小窗口操作保持可用。
- 用户关闭的效果换肤后仍关闭；用户能预测哪些设置属于当前皮肤。
- 退出后移除本插件的效果；用户仍能正常使用 DSH，并能找到再次应用的入口。
- 两套样例只用简单内容，不要求正式美术，也不引入声音、工作状态联动等新产品功能。

具体覆盖元素仍需经接口核对列清单，正式皮肤的主题和最终范围仍需收敛；技术组合的选择不能被当作用户已确认的正式首版清单。

## 约定二：模块执行位置与接口表

### 执行职责

| 部分 | 位置 | 承担责任 | 状态归属及约束 |
|---|---|---|---|
| 皮肤协调器 | DSH Host 插件侧 | 串行处理应用请求、兼容检查、配置合成、调用执行端、提交与恢复 | 皮肤选择及用户覆写的唯一提交者；具体服务接入点待核对 |
| 页面执行端 | DSH Web 页面 | 通过已验证扩展接口应用页面效果、检查可见状态、清理节点/样式/订阅 | 只报告本次操作结果；页面重载后向协调器同步，不自行提交另一套选择 |
| 页面主题模块 | 页面执行端内 | 仅处理清单中的主题表面和参数 | 不改授权、启动器或原生进程设置；设置/插件管理页先保留为恢复路径，能否隔离需验证 |
| 原生执行端及桌宠模块 | 现有 Electron 运行层 | 加载原生资源、操作现有窗口与行为、确认就绪、清理效果 | 位置和临时行为由原生层管理；皮肤选择及模块用户参数由协调器管理 |
| 宿主适配层 | 对应的 Host、页面和原生边界 | 包装官方接口、必要的集中式版本适配、消息传递和错误回报 | 未验证的 DSH 状态事件不得显示为已支持能力 |
| 资源解析器 | Host 管理资源索引；各执行端使用受控访问接口 | 按皮肤标识、内容版本/摘要、资源标识定位同一资源 | 执行端不依赖固定角色目录或作者机器的绝对路径 |

上述为目标分工，现有控制器和运行层仍需适配。现有 `settings.json` 存在多处写入，不能未经迁移就宣称已具备唯一状态来源。

### 首阶段的最小模块接口

| 接口职责 | 必须明确的内容 |
|---|---|
| 描述能力 | 模块标识、接口/配置版本、执行位置、依赖能力及受支持参数 |
| 准备 | 校验并准备本次资源；不改变当前可见外观；返回可释放的准备结果 |
| 应用与确认 | 接收操作标识和有效配置，实际完成效果后确认就绪；不得只以消息接收成功作为应用成功 |
| 更新配置 | 使用同一协调流程验证、应用和提交；失败保留上次成功配置 |
| 退出 | 可重复调用，撤销自身资源并返回结果；未知清理结果不报成功 |

请求和回报须对应操作标识、皮肤内容标识及模块，迟到回报不得改变新状态。执行端在异步准备完成及改变可见效果前，也必须核对当前有效操作标识；退出或停用先使旧操作失效，再清理资源并确认。旧操作即使随后完成，也不能重新显示窗口或插入样式；无法确认失效或清理时进入故障状态。

接口的实际函数名、IPC 格式和宿主服务绑定在能力核对后确定。

### 状态与资源边界

- 皮肤状态、全局效果偏好、每套皮肤用户覆写由 Host 协调器统一写入。原生窗口位置、临时动作及运行日志使用独立运行状态，避免两个进程反复覆盖同一设置文档。
- 启动器读取皮肤快照前先检查停止意图、未完成操作及未处理恢复请求；命中时不自动应用相应皮肤模块，等待 Host 处理。无上述情况时，Host 未就绪阶段最多读取最后提交的兼容快照，不独立提交新皮肤。Host 接管后以协调器确认的状态为准；独立于皮肤的既有启动功能仍按自身开关执行。具体行为必须单独验证。
- 页面和原生托盘的持久化参数变更均提交 Host；Host 不可用时不写皮肤配置，并明确提示。停止请求仍可立即停止本执行端，并写入带唯一标识的独立请求记录；Host 持久化停止意图后确认消费。用户后续主动应用不得被已消费的旧停止请求覆盖。
- 包通过逻辑资源标识请求资源，解析器负责根目录、支持类型、存在性、内容隔离和旧资源释放。同名文件在不同包或内容版本之间不能混用。
- 首阶段模块随插件发布。新增已支持范围内的参数通常由模块扩展；新公共能力才涉及底座接口变化。
- 仅通过已验证事件和已有动作实现样例。本阶段不建设通用互动脚本语言，也不允许资源包执行任意代码。
- 明确页面区域由哪个模块持有。其他全局皮肤插件并存的兼容情况逐项记录；不能确认时显示限制，不自动停用或改写其他插件。

### 实施前的能力关卡

| 项目 | 本轮状态 | 必须得到的证据 |
|---|---|---|
| 目标 DSH 版本和主题/插槽/生命周期接口 | 既有交接目标为 0.2.1-rc.5；新主题接口未验证 | 实施时的实际版本、对应接口位置与最小调用证据 |
| 主工作区样式能否与管理/恢复入口隔离 | 待验证 | 可覆盖元素清单、影响范围和撤销结果 |
| 原生加载就绪与操作回报 | 现有运行代码有基础；新协调协议未实现 | 操作标识与内容标识对应、错误及迟到回报处理 |
| 资源跨页面与原生解析 | 新合同待实现 | 两包同名资源、换包及更新后读取一致性 |
| 页面不可用时的恢复方式 | 待选择并验证 | 至少一条不依赖被换肤页面的真实恢复路径 |

任一关卡未通过，只能记录未验证或调整技术组合，不能以设计图或隔离测试代替宿主能力证据。

## 约定三：切换、恢复与运行状态表

### 唯一协调和成功含义

协调器区分用户请求、正在执行的操作、最后成功提交的皮肤和各效果实际结果。正常切换一次只执行一个操作，期间新增的选择保留最后一项，等待当前操作达到可处理状态；恢复/停用请求优先进入清理，具体执行端取消方式经接口验证确定。

必需能力在切换前检查。必需模块中实际启用的效果确认成功、可选效果有明确结果后，才提交本次选择。用户主动关闭的效果保持关闭，状态显示原因，不擅自重开。

停止意图仅由用户主动应用皮肤或恢复皮肤效果解除；重启 DSH、停用后重新启用插件不解除。恢复操作仍尊重各项效果的全局关闭设置；没有停止意图时，重新启用沿用既有规则。一次恢复应用失败时继续保持停止意图，不能只因点击而永久解除。

跨进程可见效果不保证瞬间同时变化；必须保证操作结果可判定、旧回报不覆盖新结果，且失败可恢复。

| 状态 | 执行内容 | 下一步与持久化规则 |
|---|---|---|
| 未应用 / 已稳定 | 展示当前已提交结果 | 接收请求；最后成功快照不因点击立刻改变 |
| 检查与准备 | 检查包、版本、依赖、用户开关和资源，准备执行端 | 失败不退出当前皮肤；通过后记录本次操作的恢复所需信息 |
| 退出旧效果 | 按资源归属清理旧效果，等待执行端确认 | 清理确定完成才进入新应用；结果未知则进入故障处理，不继续叠加效果 |
| 应用与等待就绪 | 应用有效配置，收集对应操作的执行结果 | 页面、原生资源实际就绪后确认；可选失败及用户关闭分别记录 |
| 提交成功 | 原子保存本次选择、覆写与结果，并更新用户可见状态 | 提交前最后成功快照保持不变；提交完成才显示应用完成 |
| 回滚 | 清理新效果，确认可清理后重新应用上次成功的兼容状态 | 原状态恢复成功后结束；失败转故障/停止效果状态 |
| 故障 / 清理未确认 | 尽可能停止效果，保留失败原因和上次成功配置 | 不显示成功；禁止盲目循环重试，使用恢复入口处理 |
| 停止全部皮肤效果 | 退出本插件效果，保存停止意图 | 保留授权、皮肤包及用户覆写，重启不得绕过停止意图重新应用 |

每个执行阶段都必须有有限超时、日志及可解释结果。具体时长先在目标设备做基线测量，在样例验收执行前冻结，不能边验收边调整以取得通过。

### 退出与备用恢复

- “重置本套参数”只清除本套用户覆写；“退出皮肤/停止全部皮肤效果”撤销本插件效果，两者不共用含糊的恢复默认含义。
- 退出显示宿主当前有效外观：没有其他改动时即进入前外观；若其他插件或用户之后修改了主题，不用旧快照覆盖对方的新设置。
- 正常恢复从管理入口触发。管理页面不可用时，需另有已验证的恢复通道；候选为不受换肤影响的官方插件停用路径，及已有原生托盘/启动入口可提供的停止请求。候选尚未验证，不记为已可用。
- 备用入口若在 Host 暂不可用时接收停止请求，应立即停止自己能控制的效果，并记录独立的恢复请求；Host 下次启动先处理停止意图，不直接自动应用故障皮肤。该请求不作为第二个皮肤配置写入者。
- 停用官方插件复用既有停用链路，停止页面和原生效果。重新启用、重新打开 DSH 和手动重播的区别沿用最新交接规则，并分别回归。

### 中断、重启与窗口动作

| 情况 | 设计结果 |
|---|---|
| 页面重载 | 重新取得协调器的当前操作/已提交状态；旧页面实例的回报失效 |
| Host 或原生执行端中断 | 不把接收消息当完成；记录中断，按既有进程归属规则停止并进入可恢复状态 |
| 启动发现未完成操作记录 | 先进入停止皮肤效果的状态，保留最后成功快照；提示用户恢复，不循环自动重放失败操作 |
| 主窗口最小化 | 页面动态效果按可见性暂停；若桌宠入选且用户开启，可继续运行，应用前说明 |
| 关闭主窗口但 DSH 进程仍在 | 页面不可见时暂停动态效果，页面销毁则清理其效果；已开启的桌宠继续运行，应用前说明；实际窗口生命周期须核对 |
| 真正退出 DSH / 停用插件 | 停止本插件页面效果及受管桌宠；再次启动是否恢复受停止意图和用户开关约束，复用既有进程归属规则 |
| 换肤或运行中重新启用 | 不以换肤为理由强制重播开场；正常重开 DSH 按现有动画开关运行 |

## 约定四：设置、版本与兼容规则

### 设置分区与合成

| 分类 | 保存内容 | 换肤/更新时的行为 |
|---|---|---|
| 应用级设置 | 现有授权、自动启动、启动入口及启动动画开关等 | 保留现有含义，不由某套皮肤默认值改写 |
| 全局效果偏好 | 已接入效果的启停，适用时包括静音或性能选择 | 跨皮肤保留，用户关闭优先于包的开启意愿 |
| 每套皮肤用户覆写 | 对应模块中用户实际修改过的颜色、尺寸等参数 | 按皮肤及模块分区；返回本套时恢复 |
| 包默认值 | 作者为相应内容版本提供的参数 | 不复制成用户覆写；更新时只影响未被用户覆写的字段 |
| 模块默认值 | 模块提供的兜底值 | 包及用户均未提供时使用 |
| 临时状态 | 动作、播放进度、应用中状态等 | 不当成皮肤默认值或用户设置导出 |

有效参数按“模块默认值 → 包默认值 → 当前皮肤用户覆写”合成，再进行模块校验。全局关闭、宿主能力和兼容条件决定哪些效果可以运行，不用覆盖参数值的方式表达关闭。

“必需模块”表示其实现和版本必须存在；用户全局关闭该效果时仍尊重关闭，显示“皮肤已应用，该效果由你关闭”。缺少必需能力则在改变旧皮肤前阻止应用；可选能力缺失可以跳过并列明结果。

### 用户操作的影响

| 操作 | 改变什么 | 保留什么 |
|---|---|---|
| 选择并应用另一套皮肤 | 经协调成功后更新当前皮肤及实际效果 | 全局关闭、各套用户覆写、授权与应用级设置 |
| 修改当前参数 | 校验并应用成功后保存该字段的覆写；失败提示并保留上次成功值 | 其他模块与其他皮肤参数 |
| 关闭一个效果 | 先保存关闭意图再清理对应效果；清理失败明确报告，不撤销关闭意图 | 该效果的每套参数，后续开启可继续使用 |
| 重置本套参数 | 清除当前皮肤的用户覆写并重新计算默认值 | 全局偏好、授权、其他皮肤和应用级设置 |
| 退出皮肤效果 | 关闭本插件皮肤效果并保留停止意图 | 最近使用的皮肤、参数和素材，用于之后主动恢复 |
| 更新皮肤包 | 校验并暂存新内容，应用成功后替换当前内容 | 兼容用户覆写及可恢复的旧内容；不悄悄重置用户修改 |

参数编辑采用应用成功后保存的规则，界面显示应用中/已保存/失败；关闭效果与停止全部效果是例外，先保存抑制意图，清理失败也不允许后续自动重开。Host 不可用时走独立停止请求记录，不能改写皮肤配置。不要求用户猜测保存时机。后续制作草稿与预览仍按后续功能独立设计，不复用用户已应用状态。

### 版本与迁移

- 区分插件/原生发布版本、包格式版本、皮肤内容版本、模块接口版本、模块配置版本；具体字段名和新格式版本号在接口核对后确定，不能把本文件当成现有 JSON 格式使用。
- 首阶段插件与原生组件作为一个发布单位；运行前检查兼容，版本不匹配时走既有更新/重启路径，不能一边旧执行端一边提交新协议。
- 新增可选参数给出默认值；旧参数改名或改变含义时由模块提供迁移，迁移先在副本校验，成功再提交。保留可恢复的旧数据，迁移不改授权及业务数据。
- 旧 v1 配置的迁移必须明确现有字段归属。无法识别某值来自旧默认还是用户主动修改时，优先保留该值，并记录迁移来源，不静默覆盖成新默认。
- 用户回退插件时，旧版本不被要求自动理解新配置；提供兼容快照/备份或明确阻止不兼容应用。不能用尝试读取失败后覆盖为空配置的方式处理。
- 不认识的模块配置可作为有大小等边界的原始数据保留，但不能执行；必需模块不认识则拒绝应用。根包格式不支持时拒绝应用并保留原包，不把未知字段当合法执行参数。
- 只有用户确实修改的字段才成为覆写，`false`、`0` 与未设置区分；空值是否允许由字段定义。未知数据的往返保留不得绕过资源和配置校验。

## 约定五：A/B 样例及验收清单

### 样例设计（基于已选组合的设计草案）

| 样例 | 模块组合 | 内容特点 | 用途 |
|---|---|---|---|
| A | 主工作区主题 | 简单配色与本地资源，未声明桌宠模块 | 验证模块可缺省；从 B 切回 A 时原生效果真正退出 |
| B | 主工作区主题＋现有桌宠模块 | 与 A 明显不同；沿用已有角色动作；增加一个属于已支持能力的模块参数 | 验证跨运行层协调、资源独立、模块参数分区与用户开关 |
| B 的受控异常变体 | 沿用相同选定模块 | 分别制造资源缺失、必需能力缺失、应用失败或就绪超时 | 验证应用前阻止、回滚、错误结果和备用恢复 |

A 没声明桌宠表示本插件桌宠模块不运行，不等于替用户把全局桌宠开关改为关闭。B 中桌宠若由用户全局关闭，应保持关闭并说明。

样例参数扩展需做一次开发验证：给已选模块增加一个具有默认值的可选配置，并让它控制现有能力；不改协调器、授权和其他模块的具体字段逻辑。用差异审查确认修改范围。它不是新的正式互动，也不声称旧模块会自动理解新字段。

### 验收项目及证据

| 编号 | 操作或条件 | 通过标准 | 阶段证据 |
|---|---|---|---|
| T01 | 核对宿主接口及实际版本 | 接口、影响区域和清理机制有实际依据 | 只读源码/官方接口记录，不当作运行验收 |
| T02 | 在受控官方宿主应用 A/B | 指定区域出现预期变化，基本操作正常，页面与原生状态可解释 | 独立配置环境的实际界面与运行记录 |
| T03 | A → B → A → 退出，多次请求 | 最终选择正确，迟到回报不覆盖新操作，旧效果按归属清理 | 操作标识、状态记录与可见效果 |
| T04 | 两包同名资源及内容更新 | 页面、桌宠读取各自正确版本；退出后旧资源可释放 | 资源解析与可见内容证据 |
| T05 | 修改参数、换肤再返回、重启 | 覆写作用域正确，保存时机清楚，模块设置互不覆盖 | 配置快照与实际效果对应 |
| T06 | 关闭桌宠后应用 B | 不重新开启；明确显示用户关闭，与缺少能力不同 | 界面结果与原生运行状态 |
| T07 | 缺少必需模块/版本、缺少资源 | 预检查失败不破坏当前皮肤；可选缺失如约显示 | 原皮肤保持及错误信息 |
| T08 | 应用中失败、超时、页面重载、执行端退出 | 不报虚假成功；回滚或进入停止效果状态；不循环失败 | 故障注入记录与恢复结果 |
| T09 | 管理页不可用，使用备用恢复 | 能停止效果并在下次启动尊重停止意图，授权和参数保留 | 实际备用路径操作，不能只验接口返回 |
| T10 | 重置本套参数、退出皮肤 | 两种操作含义明确、影响范围符合约定 | 用户界面及状态前后对照 |
| T11 | 长中文、代码、表格、输入、滚动、小窗口 | 已选覆盖面内可读可操作，没有遮挡或关键布局错误 | 约定窗口/缩放条件的真实任务操作 |
| T12 | 已知外观插件共存或冲突 | 仅宣称验证过的组合；不覆盖对方的新设置，冲突有下一步 | 明确的组合清单与退出结果 |
| T13 | 最小化、关闭窗口、退出 DSH、停用/启用、重开 | 行为与用户说明一致；既有启动反馈路径分别通过 | 官方 Host 与原生实际行为 |
| T14 | 模块增加可选配置，旧包再次使用 | 新字段局限对应模块；旧包有默认值可运行，其他模块不变 | 差异审查、配置校验和运行结果 |
| T15 | 当前 v1 配置迁移到本次目标格式，损坏输入及不兼容版本 | 原数据保留；不把错误配置覆盖成空白；不支持时明确拒绝 | 限定版本范围的兼容及迁移记录，不操作真实用户数据 |
| T16 | 资源消耗与应用时长 | 达到事先冻结的设备/宿主/样例预算，停止后动态资源释放 | 先测基线、再冻结指标、后执行验收 |

T15 首阶段只验证现有 v1 到本次目标格式的迁移，以及不兼容版本的明确拒绝和原数据保留；不承诺任意历史版本互相迁移，也不新增在线更新或降级管理界面。

### 分阶段结束线

1. **能力核对与设计定型**：确认最小场景和元素清单，T01 有证据；协调、配置、恢复规则已核对；实际 API、备用恢复路径及超时/资源预算的未决项有关闭条件。
2. **底座样例完成**：T02–T10、T14–T16 按实际样例检查，并完成 T11 中适用于技术样例覆盖元素的检查，至少包括长中文、代码、输入、滚动及小窗口。此时就需要受控官方宿主的体验证据，正式内容交付时再完整复验。
3. **首套正式皮肤交付**：用户确认正式模块与主题后，使用正式内容完成适用的全部项目；T11–T13 覆盖所选区域及已承诺组合，记录真实客户端验收。

本地实现、自动/隔离检查、受控宿主实际体验、打包分发/服务部署、用户真实客户端验收分别记录。不得用技术样例或构建通过代替正式内容与真实使用验收。

## 尚待验证或收敛的项目

- 已选“主工作区主题＋现有桌宠”先核对具体元素和可行性；正式模块、角色和主题单独收敛。
- 目标 DSH 实际接口、样式覆盖元素及管理入口隔离能力：没有证据不宣称支持。
- 页面失效时的真实备用恢复路径：验证前不能冻结主界面模块方案。
- 实际字段名、格式版本、IPC 和持久化迁移方式：遵循本版职责，接口核对后定型。
- 超时及资源预算：在目标设备测量后、正式样例验收前冻结并记录。
- 开源范围、许可证、创作者授权和上传目的地：后续制作功能开始前确定。
