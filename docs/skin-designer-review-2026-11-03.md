# 首套 DSH 皮肤：专业皮肤设计师视角评审

日期：2026-11-03（Asia/Shanghai）。

按用户要求，由一个皮肤设计师/视觉与交互设计师视角的 AI 子代理独立挑刺，主代理核对并整理。本次是方案与静态视觉评审，没有设计新画面、生成素材或操作真实 DSH。

## 结论与就绪度

产品和底座框架已较完整，正式皮肤的视觉设计尚未完整。当前适合进入视觉规范、关键界面和状态验证，并行核对宿主能力；还不足以直接批量制作全部页面和动作素材。现方案补齐即可，未发现需要推翻底座分层的问题。

| 层次 | 当前已有 | 仍缺什么 |
|---|---|---|
| 产品方向 | 统一入口、模块/皮肤分工、选定参考、可配置互动及默认值规则 | 正式覆盖清单和入选互动 |
| 底座设计 | 协调、资源、配置、恢复和验收约定 | 实际宿主接口、独立恢复路径和运行预算验证 |
| 视觉设计 | 档案暖白＋鲸鱼娘扫描参考，旧角色技术样机 | 一套日常视觉规范、关键页面及组件状态稿 |
| 角色与动效 | 参考扫描片及现有桌宠动作基础 | 角色对照、动作规格、素材可用清单和反馈时序 |
| 交付验收 | 工程及日常任务验收条目 | 可看的设计标准与正式内容的实机结果 |

用户随后明确：视觉规范和关键界面/状态稿，正是第一套皮肤应当沉淀的内容。因此这些作为首套皮肤的正式产物，在制作中形成并验证；不要求先把所有皮肤共用的美术规范全部定死。

## 七项主要问题

### D1｜高：参考尚未转化为日常视觉语言

场景：开场暖白与橙色强调、扫描模板蓝色强调、旧样机蓝紫控件各自成立，但组合后缺少共同规则。

依据：[覆盖与互动调研](skin-scope-and-interactions-2026-11-03.md)“选定主题与素材核对”及上游模板；主代理实际看到的档案 hero 图与旧样机也属于不同的界面表达。

最小修正：做一页视觉规范，明确主色/强调色职责、文字层级、中英文字体和代码字体、表面材质、边框圆角、间距与图标用法；同时确定首版支持哪些深浅模式及回退方式。无需重画所有图标。

时机：正式界面制作前，用关键稿验证，再随首套落地修订。

### D2｜高：角色与动作尚未完成对照

场景：扫描片角色、背景角色和 Q 版桌宠需要被感知为同一个角色；目前尚无对照证据，不能仅凭题材相同推定一致，也不能据此断言一定不一致。

依据：覆盖与互动调研“选定主题与素材核对”、现有桌宠 JPG/GIF，以及 [素材说明](../designs/dsh-companion-v1/ASSET-NOTICE.txt)。

最小修正：角色对照板放入扫描关键帧、背景角色、待机和主要动作，核对服装、头饰、尾部、比例和表情。动作表记录画布、脚底锚点、透明边缘、循环接缝及缺失项。

时机：正式角色资源锁定、批量补动作前。

### D3｜高：“全覆盖”需要细化为组件和状态矩阵

场景：主聊天页统一了，但模型菜单、工具卡片、输入禁用态、错误或设置弹层出现另一套视觉，完整感仍会中断。

依据：[整体方案](first-skin-brief.md)第9节、覆盖与互动调研“对全覆盖的建议”、底座设计约定“最小体验清单”。目前为区域与目标描述，尚不是逐组件设计清单。

最小修正：列“位置—组件—状态—模式—覆盖/保留原生”矩阵。先画主工作区、一个设置页和一个菜单/弹层组合，覆盖默认、悬停、选中、键盘焦点、禁用、加载和错误等适用状态。不能接入的区域明确保留策略。

时机：正式覆盖范围冻结前；无需首轮一次画完所有页面。

### D4｜高：可读性目标尚缺复杂背景与密集内容的视觉证据

场景：默认背景可读，不代表明暗变化、角色装饰、代码块、长消息和缩放后都可读。旧样机的信息密度不能代表真实聊天工作区。

依据：覆盖与互动调研“背景、文字与图标”目标；底座设计约定 T11 及旧样机实际画面。

最小修正：定义正文/代码的稳定表面、背景静区、装饰透明度及角色出现位置。用浅、深、复杂背景呈现同一份长消息，检查焦点、缩放和减少动态时的替代状态。

时机：主工作区关键稿阶段，全面铺开样式前。

### D5｜中高：单项互动的参数不等于完整的角色表演规则

场景：输入陪伴、任务完成、拖拽和操作彩蛋同时触发，可能动作跳变、气泡覆盖、声音叠加。每项都有冷却仍不足以判断谁应该优先。

依据：覆盖与互动调研“轻量互动候选池”“支撑各种小巧思的扩展方式”已写节流及配置，尚无入选互动的时序。

最小修正：区分需要用户处理、任务结果、主动互动、装饰彩蛋等反馈层级，定义互斥、优先级、中断点、回待机方式及动作/气泡/声音的组合。先编排少量入选项，再扩展候选。

时机：首轮新增互动选定后，动作编排前。

### D6｜中：配置规则完整度高于配置界面的设计完成度

场景：换肤后设置项隐藏、全局关闭仍生效、某些值已经自定义，用户需要能理解当前结果。模型映射等复杂项也不能仅靠字段类型生成通用输入框。

依据：覆盖与互动调研“每套皮肤的默认值与设置显示”及底座设计约定的设置规则。现有旧样机还不是新动态配置界面的设计稿。

最小修正：制作首次默认、用户已调整、部分能力不可用三种设置状态稿，明确作用范围及“默认/已自定义”。不支持项隐藏，皮肤详情说明包含哪些效果；映射类配置使用小编辑区与结果预览。

时机：首版设置页设计阶段，完整制作编辑器继续后置。

### D7｜中：来源说明还需转成可交付的默认素材清单

场景：画面和时序已经围绕某段声音或视频定稿，后续才发现素材可用范围或作者信息尚待明确，替换会影响节奏和角色设计。

依据：覆盖与互动调研“素材状态”表及现有素材说明。这是已知资源状态对设计交付的影响，不是新的法律判断。

最小修正：默认交付表区分当前验证可用、计划交付可用、待确认及替代资源。声音未选定时先验证无声体验，关键交互含义不依赖待确认音频。

时机：默认素材锁定前；未来开源制作的许可策略仍在后续阶段处理。

## 首套皮肤应沉淀的最小设计交付

| 交付物 | 首套要形成的内容 | 后续如何复用 |
|---|---|---|
| 视觉规范 | 所支持模式的颜色、文字、表面、间距、图标与组件状态 | 复用规范结构与参数机制；具体色值、字体和材质属于各皮肤 |
| 关键界面与状态稿 | 主工作区、设置/菜单弹层、启动到工作区及桌宠连贯对照 | 复用验证场景、页面模板和状态清单 |
| 角色与动作资源表 | 形象对照、动作映射、锚点/画布/循环、缺失项和可用范围 | 复用动作合同、质量检查与来源记录方式 |
| 互动时序与默认配置 | 入选玩法的优先级、中断、冷却、回待机，以及皮肤默认值和显示条件 | 复用模块接口与可配置结构；各皮肤选择玩法和参数 |
| 覆盖矩阵与视觉验收样例 | 部位/组件/状态/模式/原生保留，以及密集内容和异常场景 | 复用检查方法，在新皮肤中逐项标明覆盖情况 |

这些在首套真实落地中形成、校正和验证。底座承载资源、状态、配置及扩展合同；档案暖白、鲸鱼娘、具体字体和动画留在皮肤内容及对应模块中，不写成所有后续皮肤必须采用的全局风格。

后续开放制作时，可将合适的规范、模板、示例和检查方式整理为创作者资料；代码、文档与角色/音视频资源分别记录可公开和分发范围。现在形成可复用产物，不提前发布制作工具或扩大首版。

## 建议的下一步

先做视觉规范与少量关键稿，同时核对目标宿主接口。关键稿证明日常使用与角色风格能够成立后，再铺开正式页面和动作。现有样机继续用于技术验证；本报告不将设计建议自动记为已实现、已验证或新的首版功能。
