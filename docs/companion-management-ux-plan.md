# DSH「主题盒子」管理页 P1 原型评审稿

范围是 DSH 侧栏「主题盒子」内的皮肤库、本套设置、开始使用、授权与更新。首屏让用户看清当前生效的皮肤、哪些模块在运行，以及接下来可以做什么。沿用现有管理页组件、明暗色和皮肤封面。以下入口和文案为评审提案，范围以[路线图](skin-roadmap-2026-11-06.md#p1-管理页与首版收尾)为准。

## 管理入口分工

- **插件内管理页**负责本机皮肤、预览、偏好和恢复。P1 优先完善这个入口，用户日常管理从 DSH 完成。
- **现有运营后台**负责发码、设备授权管理和查看、下载已归档版本。Windows 分发沿 W3 的平台分流接入。[现有后台接口](../licensing/console.mjs)
- **网页制作或运营工作台**列入远期评估。等内部多套皮肤的流程跑顺，出现多人协作、作品审核或批量发布等常态需求时，优先复用现有后台及皮肤格式扩展。

## dev.33 皮肤库候选

已接入插件实际皮肤库。当前皮肤摘要显示模块状态，提供「本套设置」「预览开场」「停止本套效果」与「恢复本套」。点击封面和名称可浏览，点击「应用皮肤」切换。导入或重复导入定位对应卡片，切换失败时可在卡片重试。键盘应用成功后焦点回到当前皮肤。

本地验证使用生成的插件客户端和隔离宿主响应，覆盖上述流程、初次激活以及窄窗。2026-11-06 用户确认 Windows dev.33 验收通过。回执未另列 DSH 版本或逐项结果。

## dev.34 本套设置候选

- 保存失败时，原设置行保留当前读取值和「重试保存」。重试前回读宿主，已保存的值直接确认，尚未保存的值重新提交。同一批次中其他字段继续保存。
- 「重置本套」在页脚展开确认，告知只恢复本套参数默认值，模块开关和全局自动播放偏好照旧。可取消或按 Esc，确认后才调用现有重置接口。
- 使用生成的客户端和模拟宿主响应验证失败后重试、响应丢失时避免重复写入、并行编辑、重置取消和确认，以及窄窗口。2026-11-06 用户确认 Windows dev.34 验收通过。

## 原型走查路径

| 用户任务 | 原型调整 |
| --- | --- |
| 首次使用 | 保留皮肤库为日常入口。读取状态时显示「正在读取」，确认未激活后才给出「激活插件」。开始使用聚焦激活和返回皮肤库选用。已激活时可直接进入皮肤库。旧配置包和无皮肤时的桌宠控制保留原行为，置于次级入口。 |
| 导入、换肤、预览 | 「导入本地 ZIP」说明包根目录需含 `skin.json`。导入成功定位到该卡片，标为「已入库」并给出「应用」按钮。取消回到原列表，重复导入定位已有项。浏览卡片信息与提交应用分开。当前皮肤摘要集中显示名称、版本、效果状态和模块状态，提供「本套设置」与可用时的「预览开场」。未应用皮肤可浏览封面与能力，播放开场复用当前已应用且开场就绪的条件。 |
| 日常设置 | 页标题直接使用「本套设置」和皮肤名。常用优先放桌宠开关、大小、工作区主题与开场开关，再放开场预览。自动播放标为「全局偏好」，明确需完全退出 DSH 再从原图标打开。模型、互动参数、映射与触发条件归入更多。按皮肤声明展示控件、默认值与覆写状态。已声明但不可用的模块就地说明原因。 |
| 恢复与更新 | 当前皮肤摘要放一个「停止本套效果」或「恢复本套」入口。「重置本套」收进更多，确认框写明将清除本套参数覆写，模块开关与全局偏好照旧。插件级停用、解绑及恢复说明在「授权与更新」。更新区分别显示已装版本、宿主兼容性、可下载版本与下载结果。安装成功以 DSH 重新读取到已装版本为准。 |

## 状态与恢复

- **已入库 → 应用中 → 已应用**。申请切换时同时显示上次成功应用的皮肤和本次目标。过渡期间以宿主状态标记效果是否仍在运行。失败后按宿主回读结果显示实际状态。若清理或回读失败，显示「需要恢复」并给出「重新检查状态」或「切换到可用皮肤」。
- **设置保存中**。反馈放在对应设置行。失败时显示最后确认值，并允许重新提交本次修改。重试前先回读，确认皮肤仍相同且目标值尚未保存。复用已有请求顺序、同字段合并和停止优先处理。
- **单模块已关闭、模块不可用、整套已停止**分别表达。关闭模块保留其参数。停止整套恢复 DSH 默认外观并保留皮肤选择、覆写和模块开关。恢复按原选择与偏好重新应用。文件缺失或校验失败时保留偏好，提示切换其他可用皮肤或重新导入原包后再尝试。
- **无法继续时提示下一步**。授权失效定位到激活或刷新。ZIP 校验失败说明可修复原因。预览不可用说明需启用哪个模块、恢复哪套皮肤，或该宿主存在什么限制。加载、取消、失败与成功用文字区分，关键结果可由辅助技术读出。

## 复用与验收

- **复用**。以 W3 验收基线中的 `skin-settings-ui.mjs`、`Page`、`client-requests.mjs` 为界面入口，沿用皮肤库校验和 `contentKey`、授权、宿主状态与皮肤配置接口。导入、应用、保存、模块开关、停止、重置分别复用 `skinInstall`、`skinSelect`、`skinConfigure`、`skinDisable`、`skinStop`、`skinReset`，开场预览用 `replayIntro`。依据现有清单与模块状态渲染，使用宿主结果确认生效。
- **原型评审**。用「未激活首次进入」「ZIP 已入库、另一套仍生效」「换肤失败可恢复」「已停止且保留偏好」四个场景走查。确认用户能从首屏指出当前生效的皮肤并完成下一步。宽窗沿用侧导航，窄窗将页内导航移到顶部、卡片和设置单列，操作和状态保持可见。
- **Mac 和 Windows 正式验收**。分别用真实 DSH 隔离环境覆盖新装激活、ZIP 成功/取消/重复/无效、双向换肤、预览自然结束与跳过、保存失败后恢复、模块开关、停止/恢复、确认或取消重置。核对 DSH 草稿、授权、各套偏好及重开后的显示和实际效果。双端补验明暗、窄窗、Tab 焦点、Enter/Space 和 Esc。Windows 记录宿主版本、100%/125% 系统缩放及标题栏安全区，分别验证完全退出与关闭窗口到托盘。Mac 核对系统减少动态与原生窗口按钮。
- **排期边界**。W3 等待实机回执期间可评审流程和原型。W3 RC 完成后才接入真实管理页。Windows 私有查询与下载的平台分流、两版 RC 的兼容矩阵、插件与宿主分别覆盖升级和状态保留由 W3 实测，P1 消费这些结果。Stable 随官方发布补验。第二套皮肤、制作编辑器和上传属于各自的后续阶段。
