# 主题盒子：用任意 Agent 独立制作、交付和更新皮肤

适用：主题盒子 1.1.0-dev.3 本地候选，兼容 1.0 皮肤配置合同。独立制作工具包不含管理员凭据，不需要访问本项目源码或修改插件。

## 0. 先选制作流程

主制作流程已区分 A（你本地／自己的 Agent 制作，完成后自行上架）和 B（第三方独立制作，交付后由管理者接收上架），详见 [皮肤制作与上架流程](skin-kit-v1/developer-guide.md)。本文件是两条路径共用的具体操作说明。工具包内从 SKIN-SELF-DELIVERY.md 打开同样的 skin-kit-v1/developer-guide.md 即可。

## 1. 给其他 Agent 的任务说明

可以直接复制以下要求，并提供 `dsh-skin-author-kit-1.1.0-dev.3.zip`：

> 请解压主题盒子皮肤制作工具包，先读 SKIN-AUTHOR-REFERENCE.md、SKIN-SELF-DELIVERY.md 和 skin-kit-v1/developer-guide.md。以 sample/ 为起点制作一套独立皮肤。保持角色、主题、开场、声音与文案一致；只声明真实提供且引擎支持的功能，不添加任意 JS、CSS 或可执行文件。最终交付可导入的 `<id>-<version>.zip`、交付说明、素材来源/许可文件、SHA-256 和校验结果。皮肤 ZIP 根目录必须是 skin.json，不能再套项目文件夹。不要重新打包或修改主题盒子插件，不要在皮肤中放激活码或管理密钥。

主题风格、素材包、是否带桌宠以及平台目标另外写给制作者。资料中的后续能力不是当前已实现功能；不应先做素材再假定引擎一定能播放。

## 2. 制作者的交付文件

```text
delivery/
  <skin-id>-<version>.zip
  DELIVERY.md
  SHA256SUMS.txt
  checks/
    mac-dsh-<version>.json
    windows-dsh-<version>.json
    实机截图或录像
```

ZIP 内：

```text
skin.json
assets/...
LICENSE.md
NOTICE.md                 # 有需要时提供
```

- `skin.json` 的 `id` 是稳定身份。更新同一套必须保持不变；名字可以调整。
- 每次正式交付提升 `version`，如 1.0.0 → 1.0.1。已上架版本不能换内容后仍沿用原版本。
- `DELIVERY.md` 写清版本、支持的 DSH/插件版本、包含模块、各默认开关、配置变化、实机已验/未验项、已知限制和素材许可位置。
- `LICENSE.md`、description 和每项 assets.*.license 应相互一致，准确说明实际获准的使用/分发范围；不得用试作阶段的“仅本地自用”包冒充已获准分发的正式包。
- 模块缺失就省略，例如无桌宠包不声明 pet；不要放一个无实现的开关作为占位。

## 3. 无需访问项目源码的本地校验

解压工具包，安装 Node.js 22.19 或更新版本。在工具包根目录运行：

```sh
node scripts/skin-author-check.mjs /绝对路径/my-skin-1.0.0.zip --dsh-version 0.2.2-rc.1 --platform darwin-arm64
node scripts/skin-author-check.mjs /绝对路径/my-skin-1.0.0.zip --dsh-version 0.2.2-rc.1 --platform win32-x64
```

校验器已经带齐依赖，无须 npm install。Windows 也可以运行同样命令，路径按本机填写。

通过只代表清单、ZIP、资源引用/哈希/文件头和版本声明通过。`--platform` 选择目标记录，不会替你启动那个操作系统；两个命令都通过不等于已做 Mac/Windows 实机验收。

计算文件摘要：

```sh
# macOS
shasum -a 256 /绝对路径/my-skin-1.0.0.zip
```

```powershell
# Windows PowerShell
Get-FileHash 'D:\delivery\my-skin-1.0.0.zip' -Algorithm SHA256
```

把真实输出填入 SHA256SUMS.txt，不要手写猜测值。

## 4. 自行安装、验收和交给别人

1. 在 DSH 插件页安装对应平台的主题盒子 `.tgz`，并激活。
2. 打开「主题盒子 → 皮肤库 → 导入本地 ZIP」，选择皮肤 ZIP；不要把 ZIP 填进 DSH 的添加插件框。
3. 导入成功后点「应用皮肤」。导入本身不切换当前外观。
4. 检查明/暗主题、窗口缩放、图标、默认开关、开场预览/完整播放/跳过/静音，以及从原 DSH 图标完全退出后重开的自动开场。
5. 对皮肤实际提供的人设/回复风格、三类提示和场景映射逐项检查；场景先绑定真实模型/工作区，再触发。无桌宠包不要求出现桌宠。
6. 换到其他皮肤再换回，检查设置保留。停止后检查原生外观恢复，恢复后检查偏好仍在。
7. 卸载当前皮肤，检查效果停止且资源移除；默认保留设置，重新导入应恢复原偏好。勾选清除时才清本套设置。
8. 将 ZIP、说明和记录直接交给使用者；对方也可按上面的本地导入流程安装。无需找原开发 Agent 改插件代码。

## 5. 正式在线皮肤库上架与后续更新

这是管理者操作，和皮肤制作相互独立。当前提供发布工具，尚无后台自助上传界面；线上服务必须先部署包含 `/v1/skins/*` 和 `/admin/skins` 的版本。旧线上服务不支持时不要把命令失败当作已上架。

在主题盒子项目根目录，使用有服务器维护权限的机器/Agent：

```sh
DSH_CLOUD_SSH_KEY='/管理员私有路径/localSSH.pem' node <运维目录>/cloud-admin.mjs publish-skin '/交付路径/my-skin-1.0.0.zip' '展示名称'
```

这个命令先运行与插件相同的皮肤校验，再传输 ZIP，由服务器验证和登记版本/文件 SHA；密钥仅在管理机器使用，不放进皮肤或制作工具包。返回 skin.id、version、releaseId、sha256 后仍需验证激活后的实际库列表和下载。

更新时交付新版本，再运行同一命令。用户看到「下载更新」，下载后自己决定何时应用；旧选择不会突然被替换，已有个人偏好按 skin id 保留。旧版本可以自行卸载。

同 ID 的版本更新和重新下载安装不重复占下载名额。不同 ID 是另一套皮肤；服务器按激活码累计已领取 ID 计数，卸载或重装插件不返还名额。数量 0 表示不限量，包括未来新上架皮肤。

如果皮肤使用了引擎新增接口，应同时注明最低插件版本。不能仅修改 ZIP 就使旧插件获得未实现的渲染、动作或声音能力。

## 6. 给无项目上下文的 Agent

只制作皮肤：交工具包、素材与具体设计需求即可，不给服务器密钥。

维护在线皮肤库：另外交本项目目录、本文、当前发布目标、待发布 ZIP 的准确路径/版本/摘要，以及维护机器已有的 SSH 配置。要求它先校验，再上架，再用临时测试授权检查下载，不能自行给用户发码或改现有激活码配额。
