# 主题盒子 · 皮肤制作与交付流程

## 1. 要做成什么

让工作区主题、开场、角色、声音和交互形成同一个场景。无桌宠主题靠工作区与开场成立；带桌宠主题把同一角色延续到系统桌面。二次元、立绘、科幻、赛博和动漫都是可选方向，具体世界观由每套皮肤决定。

皮肤作者负责角色与视觉方案、素材、默认文案与配置、ZIP 和自测。引擎线负责 DSH 接入、授权、跨平台宿主、原生桌宠及能力扩展。用户从原 DSH 图标启动，在「主题盒子」内管理；皮肤不另做启动器。

## 2. 版本、交付与已支持范围

当前工具候选：主题盒子 `1.1.0-dev.5`，构建号 `10005`，兼容 1.0 配置合同；运行目标为 Mac ARM64、Windows x64，官方 DSH `0.2.1-rc.4`、`0.2.1-rc.5`、`0.2.2-rc.1`。兼容范围按实际验收矩阵记录，不能外推到其他版本。

| 能力 | 作者如何提供 | 素材或文字 | 边界 |
| --- | --- | --- | --- |
| 明暗工作区主题 | `modules.theme`，接口 1，推荐配置 3 的 `commander-v1` | 明暗色板、可选静态背景与语义图标 | 复用既有界面结构；自定义布局、字体文件和任意 CSS/JS 需引擎扩展 |
| 入口徽记与卡片封面 | `entryMarks` / `entryMarkEnabled`、顶层 `cover` | 明暗透明 PNG；封面 PNG/WebP | 封面 ≤2 MiB。入口徽记与 50 个工作区图标分开交 |
| 开场 | `modules.startup`，接口 1、配置 3 | H.264/AAC MP4 + 同构图 PNG/WebP 静帧 | 1–15 秒，准确填写实测时长。声音由同一成片静音控制 |
| 工作区回复风格 | 顶层 `replyStyle` | 默认称呼与语气 | 默认开启，新会话沿用本套最近选择，明确开关的会话保留自己选择 |
| 共用角色 | 顶层 `character` | 身份、工作区和桌宠场景补充 | 两端独立启停，工作区主题角色仍需逐会话开启 |
| 三类工作区提示 | 顶层 `workspaceCues` | 每场景文案、时长、位置、动效、可选明暗颜色 | 有容器与预览；尚非角色视频演出或新会话开场接口 |
| 模型/工作区场景 | 顶层 `scenePresets` | 模型徽记或立绘、工作区明暗强调色、可选问候 | 用户在设置绑定实际 provider/model 或工作区 ID；默认可回退 |
| 基础桌宠 | `modules.pet`，接口 1、配置 2 | 透明待机、回应与动作描述 | 原生驱动必须能执行该动作；不能靠写名字自动获得物理移动 |
| 模型桌宠互动 | persona、modelSelection、historyRounds、allowSpeech、allowActions 等 | 人设、短句回退、动作语义 | 当前文字气泡；预录语音和 TTS 不是该开关自动提供的能力 |
| 自主活动 | `pet.config.activityDescriptions` | 有限短动作及语义 | 从当前可用动作中选或保持安静，遵守工作、勿扰、打断与落点约束 |
| 连续陪伴 | `pet.config.interactionMemory` | 默认开关和互动偏好 | 最近 20 条专属互动/实际动作，按皮肤保存，可查看、清空和重置 |

不带桌宠的包省略 `pet` 及其资源，设置页随声明隐藏能力。普通皮肤不应写冷启动的兼容内容键或私有后端注册表。

## 3. 两套制作与交付流程

先选路径，再按各自的交付边界推进。这里的“本地制作”是制作方式，不代表只能自用；本地做好的正式皮肤经过验收后由作者自行分发或导入。两条路径使用同一份 skin.json 合同和同一套校验器，不要求另写主题盒子插件。

| 项目 | A：你本地自行制作／自己的 Agent 制作 | B：第三方独立制作 |
| --- | --- | --- |
| 起点 | 你的项目资料、素材与制作需求，也可以使用独立工具包 | 独立作者工具包、明确需求和可交付素材 |
| 制作环境 | 你自己的工作区或其他 Agent 的本地目录 | 制作者自己的环境，无需私有仓库或本机路径 |
| 交付对象 | 你自己先安装验收，再决定自用或对外分发 | 先交给你验收，也可以本地导入自用 |
| 分发 | 由作者本人决定，可自行导入或分发 | 制作环节不接触他人账号、密钥或激活码 |
| 最终交付 | 按 A7–A9 冻结独立 ZIP，由作者自行分发 | 交付验收通过后，由作者本人决定分发方式 |

### A. 你本地自行制作，完成后自行交付

1. **确定范围。** 选择无桌宠或带桌宠，写主题/角色、工作区、开场、声音和互动目标。标出本次做、可选与后续；不要把后续能力写成已实现配置。
2. **冻结视觉母版与最小小样。** 固定角色轮廓、配色、标志物、称呼和语气。从 sample/ 先改稳定 id、色板与入口标记，导入跑通，再添加其他模块。
3. **制作素材并填写清单。** 按对应版本的素材表交图片、图标、视频、声音与文字；每项记录尺寸、时长/循环、透明度、字节数、SHA、来源及实际许可。先确认一小段真实显示/播放效果，再批量生产。
4. **组装配置和 ZIP。** 每个公开配置项填写本套默认值，未提供的模块省略。ZIP 根目录直接是 skin.json。另留源文件包，供后续迭代，不把工程文件塞进运行包。
5. **运行离线校验。** 用同版 skin-author-check 检查目录和最终 ZIP，输出目标 DSH/平台、版本、内容摘要及模块结果。制作工具包自带依赖；命令见第 6 节。
6. **本地安装验收。** 在主题盒子内导入→应用，逐项测试实际声明的配置、明暗、窗口缩放、工作流、预览/静音/跳过/原 DSH 图标冷启动、换肤、停止恢复、卸载与重装。分别记录真实测过的 Mac/Windows，不能拿校验器的 platform 参数代替实机。
7. **冻结交付物。** 保存 `<id>-<version>.zip`、DELIVERY.md、SHA256SUMS.txt、素材许可/署名、校验与实机记录。再次确认运行包没有试作说明与正式分发目标冲突的文案。
8. **自行导入交付。** 用主题盒子的皮肤库导入这个独立 ZIP，不需要把它重新塞进插件 `.tgz`。导入方式见第 9 节。
9. **验证导入结果。** 核对皮肤库里的 id/version 与冻结包一致，实际导入→应用，逐项复测声明的配置、明暗、窗口缩放与桌面行为。只有通过这一段才记为可交付。

其他 Agent 也可以承担 A1–A7。把需求、作者工具包和输出目录给它即可；A8–A9 由作者本人完成，不把任何账号或密钥写进皮肤与交付包。

### B. 第三方在自己的环境中制作并交付

1. **项目方交制作任务。** 交独立作者工具包、世界观/角色与功能范围、素材清单、目标平台和插件版本；说清源文件、运行 ZIP、许可说明与自测记录是否都在交付范围。
2. **第三方独立制作。** 在自己的目录解压工具包并修改 sample/，按照同一份能力表制作素材、默认配置和最终 ZIP；不依赖本项目的 `.local/`、某位用户的绝对路径或冷启动私有注册信息。
3. **第三方校验和自测。** 在工具包根目录运行离线校验；使用已安装并激活的主题盒子本地导入。制作方有哪种机器就记录哪种实测，其余明确标记待验。
4. **第三方正式交付。** 提供 ZIP、DELIVERY.md、SHA256SUMS.txt、许可/署名、所约定源文件、填写后的素材/声音/动作表与截图/录像。目录结构和可复制命令见 [独立交付操作说明](../skin-self-delivery.md)。工具包中对应文件名为 SKIN-SELF-DELIVERY.md。
5. **你或维护方接收验收。** 对照原需求、摘要与配置逐项核验。皮肤文案/素材/打包问题退给制作者；实际需要新增引擎能力的问题交引擎线处理，不要求对方私改插件绕过。
6. **选择交付方式。** 仅本地使用时，导入通过即可保留；要对外分发时，作者按 A7–A9 和第 9 节完成导入验收，再决定分发范围。第三方完成 ZIP 不代表已经自动交付。
7. **第三方后续更新。** 稳定 id 不变、提升 version，重新提交最终 ZIP、变更说明、SHA 和受影响的回归记录；维护方验收后发布新版本。不得悄悄替换同名同版本已发布包。

独立制作工具包不携带任何账号、密钥或服务凭据；第三方交付 ZIP 后由作者本人决定导入或发布方式。

### 两条路径共用的制作原则

- 配置和素材一起设计：默认值、触发场景和可观察结果要对应；没有能力不显示占位开关。
- 带桌宠/不带桌宠是每套皮肤的选择，两条制作路径都支持；不为无桌宠主题要求桌宠素材。
- 导入、安装、应用、本地验收和用户验收分别记录，不混成一个“完成”。
- 源工程、运行 ZIP、插件安装包、管理员凭据各有用途；对外皮肤只携带内容与声明。

## 4. 包结构和接口实现

作者主要实现声明，不需要写插件或重新做模型执行器。

```text
my-skin/
  skin.json
  assets/
    icons/light/*.png
    icons/dark/*.png
    cover.webp
    opening/still.png
    opening/film.mp4
    pet/idle.webm          # 只有带桌宠版需要
    pet/react.webm
```

ZIP 根目录必须直接有 `skin.json`。包格式 `formatVersion: 2`，ID 为 3–64 字符的小写字母/数字/连字符，以字母开头；同一套迭代沿用 ID，版本用 `X.Y.Z`。`dshVersions` 明确列实测版本。每个模块有 interfaceVersion、configVersion、required、config、settings。固定值/资源引用写 config，用户可改项写 settings，settings 的每项须有 label 与合法 default。

资源条目填写 path、mime、bytes、sha256，建议同时填 width、height、alpha、source、license。图片 ≤8 MiB；视频 ≤16 MiB；封面/场景立绘 ≤2 MiB；总资源 ≤128 MiB，最多 128 项。MP4 当前仅用于 startup v3。完整图标会占约 100 项资源，新增大量变体/动作前先核对总数。浅深能共用同一图时可引用同一资源 ID。

- `theme`：色值对应 `theme-tokens.json`，每项同时交 light/dark。使用 commander-v1 时提供 semanticIcons 与 workspaceDetailsEnabled。纯静态场景可省略 workspaceRole；1.1.0-dev.3 的 commander-v1 角色位只要求 avatar PNG，可选成对的 name/model，不要求 WebM，当前显示小头像与状态。模型徽记/头像也可用 scenePresets。
- `pet`：基于现有 pack，固定动画槽包括 idle、look、walk、run、stretch、eat、play、greet、react、sleep-in、sleep、wake。先接 idle/react；部分动作集使用配置 2。每段填 asset、seconds、loop。桌宠动作的实时位移、道具层或窗口边接触由引擎验证。
- `startup`：poster、video、seconds、handoffSeconds、stillSeconds、greeting、subtitle。时长以成片实测为准；MP4 解码时长与声明偏差 >0.1 秒会回退静帧。soundEnabled=false 直接静音同一文件，无需另交静音运行片。
- `replyStyle`：address ≤32 字，tone ≤280 字。提供正常任务、报错解释、详细展开三组示例。
- `character`：name ≤32、identity ≤2000、workContext/petContext 各 ≤600 字；至少一个场景。petEnabledDefault 决定桌宠是否默认共用；工作区开关独立。
- `workspaceCues`：welcome/session/workspace 分别声明 text ≤72 字与 default，可选 seconds 1–8、position、effect、colors。各条分别可配置与预览。详见配置参考。
- `scenePresets`：model/workspace 每组最多 8 个；徽记/立绘引用 PNG/WebP，工作区 accent 提供明暗色。映射由用户选择，作者交默认组和每组用途。
- `interactionMemory`：enabledDefault 布尔值、preferenceDefault ≤400 字，均必填。无需额外图像或音频；按皮肤保存。

完整节选和字段名以同包 `configuration-reference.md` 与工具包校验器为准。不要向清单加入尚未支持的 media、audio 或自定义脚本字段。

## 5. 素材产能与转换分工

当前素材人员可交 H.264/AAC MP4（1280×720）、PNG/WebP、48 kHz/24-bit 立体声 WAV，无需采购或学习 WebM、Lottie、AE 工程来完成无桌宠主题。开场直接使用有声 MP4。

透明桌宠运行文件当前仍需 VP9 Alpha WebM。美术可交**透明 PNG 序列**和帧率、脚点、首尾说明，由接入方准备转码工具；仅有不透明 MP4 时，不能假定已有透明桌宠。单张 PNG 可用于静态头像/徽记，不冒充动画。先做一小段转换与实机确认，再生产整组。

## 6. 开发者自测

```sh
node scripts/skin-author-check.mjs my-skin.zip --dsh-version 0.2.2-rc.1 --platform darwin-arm64
node scripts/skin-author-check.mjs my-skin.zip --dsh-version 0.2.2-rc.1 --platform win32-x64
```

校验器来自同版作者工具包。真实操作要覆盖：导入→应用→明暗切换→阅读代码/表格→输入与发消息→每项设置→三类提示预览/实际触发→开场自然结束/跳过/静音→完全退出从原 DSH 图标重开→换肤→停止/恢复→覆盖升级保留。带桌宠另验透明命中、缩放、拖拽、动作结束回待机、模型说话、共享角色和连续陪伴。

## 7. 最终提交物

皮肤 ZIP、版本号与摘要；源文件与导出成品；填好的资产/音频/动作表；授权与署名文件；明暗截图、开场与交互录像；平台/DSH/插件版本与通过/未过清单。安装包、模型密钥、机器授权由项目方分别提供，皮肤包只携带内容和配置。

## 8. 后续需求如何提

角色欢迎演出、新会话空白页开场、工作区完整过渡、多方向走跑/坐靠/攀爬、道具、事件音效、TTS、自定义字体和作者编辑上传仍在路线图。交触发、预期画面、最小素材、当前结果、可接受简化；先让引擎线确认接入，再把它写成皮肤承诺。

## 9. 本地导入与验收

### 9.1 导入方式

- 主题盒子 →「皮肤库」→「导入」，选择 `<id>-<version>.zip`；导入后按需应用。
- 未启用主题盒子时，也可按 DSH 插件安装方式安装本地包；本插件本身不内置皮肤。
- 导入只读取 ZIP 根目录的 `skin.json` 与声明的素材，不执行包内脚本。

### 9.2 导入前自查

```sh
node scripts/skin-author-check.mjs '/绝对路径/my-skin-1.0.1.zip' --dsh-version 0.2.2-rc.1 --platform darwin-arm64
node scripts/skin-author-check.mjs '/绝对路径/my-skin-1.0.1.zip' --dsh-version 0.2.2-rc.1 --platform win32-x64
shasum -a 256 '/绝对路径/my-skin-1.0.1.zip'
```

- 锁定 id、version 与 SHA-256，确认与交付说明一致。首次导入用新 id；更新已导入皮肤保持 id、提高版本。
- 校验器只检查结构与清单，不代替真机验收。

### 9.3 导入后的核对

1. 皮肤库中的名称、封面、模块、兼容范围与版本应与冻结包一致。
2. 导入并应用后，逐项复测实际声明的配置、明暗、窗口缩放、工作流、预览/静音/跳过/原图标冷启动、换肤、停止恢复、卸载与重装。
3. 更新旧皮肤时，旧版保持当前选择，用户点击「下载更新」后再决定应用；确认设置保留、重装不重复占用名额，旧版本可卸载。
4. 记录包、摘要与验收结论，保留可复查的源文件与旧版本原包。

### 9.4 更新和失败处理

- **新版本更新：** 沿用 id、提升 version，重复校验→本地验收→导入→回归。只更新内容不需要重装插件；用到新增引擎能力时注明最低插件版本。
- **导入失败：** 按错误码修正清单或素材后重做 ZIP；不要靠改原版本 ZIP 的途径覆盖已导入内容。
- **同版本不同内容：** 明确升版本，不覆盖同 id/version 的既有包。
- **功能回退：** 保留旧版本原包，用户可换回本机保留的旧版本；不要删除用户的导入记录来“回退”。

若部署了自建皮肤分发服务，可把它当作可选的导入来源；开源版不提供任何托管服务，也不要求联网。
