## 用户新增的模型驱动方向如何影响后续

用户在皮肤对话本轮提出“行为模式可以增加交给大模型去控制的配置”，进一步说明“我们可以提供的是桌宠能力，能力让大模型决定怎么去执行”。这改变的是后续行为设计的深度，不是本轮停止/状态修复的正确性。

下一轮补充设计应明确：

1. 行为模式如何选择本地规则、模型驱动或混合；这些是待收敛的方案，不把全部模式自动承诺为首版已实现能力。
2. 本套角色人设、主动程度、情景输入、允许调用的能力，以及模型选择、调用频率和不打扰偏好如何配置。模型选择动作与短句，本地完成动画、移动和时序执行；没有匹配资源或请求失败时使用简明的本地回退。
3. 复用现有 DSH 模型/工具接口或合适的开源桌宠能力，说明具体可复用部分。新增桌宠决策模块，继续使用现有加载、资源、配置和停止/恢复，不重做整套底座或另建通用 Agent 平台。
4. 用一组真实可验证的情景形成最小闭环，并明确哪些只是模拟。完整制作器、上传、市场仍后置，外部壁纸兼容仍不做。

皮肤线已在调研公开项目，主控不重复同一调研。待其补充设计完成后，只对新增模式、配置及接入改动验收。idle/react 的少量完整动作样本可继续独立试制，不因本轮范围外能力未完成而停止全部制作。

本轮没有新增阻塞缺陷，也没有操作真实安装/profile、提交、推送、发布或部署。
