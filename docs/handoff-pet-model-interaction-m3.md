# M3 桌宠模型互动最小闭环

2026-11-03（Asia/Shanghai）。用户已在首套皮肤对话回复“同意”，确认“提供桌宠能力，由模型结合人设、情景和近期互动决定如何使用，本地执行并记录实际结果”的核心方向。主控已读取该回复及前一轮方案。用户随后要求离开期间按现有模式持续推进，子任务上报后由主控审核并接续。

## 本轮做什么

先打通一组连续互动：

用户点击或向桌宠输入 → 本套人设、最近 N 轮桌宠互动及过去实际动作、当前可用能力 → DSH 已配置模型 → 一句短话、一个已有动作或安静 → 现有执行器执行 → 实际结果带入下一轮。

先实现说话与已有动作。用户接着说“换个动作”时，模型应收到上次实际做过什么；不只保存模型原本想做的动作。允许没有动作或安静，不为了凑效果执行不存在的资源。第一条完整路径可先选现有插件中的桌宠专属输入，点击复用相同服务，不为入口另建一套模型循环。

近期互动只指桌宠自己的上下文；不默认导入无关工作会话。先做最近轮次，不建设长期记忆/RAG、定时自主决策、识屏、移动规划、语音或通用 Agent 平台。R4 的其他候选不自动升级为本轮必做。

## 分工和复用

- **底座/模块线**：在已有插件与 pet/decision 职责中实现模型配置、调用、上下文、动态短句及已有动作执行；核对并复用官方模型目录、当前选择、ctx.llm 和适合的工具注册。具体接入依据本线 model-decision-interface-audit-2026-11-03.md。
- **皮肤线**：独立 R4 配置和连续互动原型，提供首套人设、真实动作语义及默认配置；明确哪些是模拟、哪些已进入运行模块。保持已验收 R3 可追溯，不修改底座文件。idle/react 的少量完整动作可继续独立试制。
- **主控**：收敛范围、读取共享进度、独立验收并回传下一步；不重复两条线的调研或实现。
- 已有加载、资源、授权、逐皮肤覆写、原生运行层、停止/恢复继续使用；角色、人设和首套参数不硬编码进公共协调器。复制开源代码时保留对应来源与声明。

## 配置与模块接缝

首轮必要配置：智能互动启停、本套人设、跟随当前或指定 DSH 模型、近期历史轮数、允许说话和已有动作。皮肤提供合法默认值，用户覆写按本套保存；不支持隐藏、不可用解释原因。默认值由 R4 和模块合同收敛，不把所有候选字段提前塞入当前 M0。

本轮先做混合分工：待机/物理和即时本地行为继续本地运行，明确的点击或对话触发一次模型决策。不逐帧调用模型。动态短句和动作仍服从用户关闭、当前皮肤、需要处理状态与全局停止；停止期间到达的旧结果不能重新显现。

上下文与执行结果采用足够表达当前场景的小型结构即可，由模块线落为实际接口；复用现有取消及操作身份，不再造通用权限/调度框架。

## 可观察的交付条件

1. 两轮桌宠互动实际通过模型调用链；第二轮请求带第一轮已执行的短句/动作结果，人设与可用动作能从本套声明取得。
2. 模型选择一个真实已就绪动作或不动作，短句在现有桌宠呈现；无效选择/请求失败走简明本地回退并记录实际结果。
3. 关闭智能后仍可使用本地回应；已有大小/气泡等适用偏好保持生效。
4. 请求等待中停止，晚到结果不能重新开启；恢复及皮肤切换继续沿用已有规则。
5. 配置默认、覆写、重置和能力不可用的结果可复现；相关测试与此次改动相称，不无故重跑未变化的完整旧矩阵。

若隔离环境没有可用模型，先完成实现和可重复的模拟/适配验证，明确指出真实调用还缺什么，不把夹具响应标作真实模型验收，不借此读取用户私聊或替换真实 profile。优先使用已配置且允许的模型路由；本轮不新增付费服务或替用户购买额度。

## 阶段与交付边界

先完成 R3 五字段定向联调的报告/清理，再进入本轮；不重开已经通过的返工项。底座线维护自己的合同、源码、报告和 progress.json；皮肤线维护自己的 R4 产物和 integration-needs.md。两条线阶段完成后主动交主控审核，期间保持可独立推进。

真实安装/profile 改写、部署、提交/推送/发布边界不变。制作器、上传和市场后置，外部壁纸兼容不做。模型能力通过不等于全身服装、完整新角色动画或全部自主玩法已验收。
