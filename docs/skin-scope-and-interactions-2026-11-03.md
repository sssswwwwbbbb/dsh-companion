## 对“全覆盖”的建议

建议把正式目标定义为“常用流程中的视觉统一与角色连续性”，覆盖清单如下；这是建议，还需按实际 DSH 能力确定边界。

| 体验区域 | 建议的一致性 |
|---|---|
| 启动与进入 | 选定的档案/扫描风格、文字及过渡，与正常启动和跳过规则一致 |
| 主工作区 | 侧栏、会话、消息、代码/表格、输入、工具和模型控件使用统一视觉层次 |
| 常用辅助页面 | 设置、插件页、菜单、弹层、提示、错误和禁用状态在色彩与组件规范上衔接 |
| 背景、文字与图标 | 背景服务于内容；字体清晰；成套主题功能图标覆盖常用导航、会话/消息、输入/附件、文件工具、状态及设置，保持语义与视觉语言一致；复用来源及许可明确 |
| 桌宠与角色反馈 | 角色、动作、气泡、菜单和界面角色元素协调，日常操作可得到适量反馈 |

开场可以有较强叙事，日常工作界面以可读与流畅为基础。普通操作不加入长时间阻断式动画，真实权限和错误提示保留原有含义。备用恢复路径必须独立于可能被换肤影响的页面。

“全覆盖”不扩展为支持所有第三方私有页面、改写系统桌面或兼容外部壁纸格式；系统原生区域及无法稳定接入的区域要明确边界，不把无法实现的位置写成已覆盖。

## 适合 DSH 的“小巧思”候选池

以下是设计建议，不因列入调研而全部成为首版承诺。优先区分现有基础完善与新增体验。

| 编号/方向 | 触发与反馈例子 | 可配置内容 | 前提与适合程度 |
|---|---|---|---|
| I01 主动互动 | 摸头有表情，投喂后回应，拖起后松手落地 | 动作组、气泡、频率和声音 | 有现有基础，先完善手感与角色一致性；不冒充全新能力 |
| I02 回来招呼 | 一段时间未操作后回到 DSH，角色抬头、挥手或一句问候 | 间隔、时段、台词、是否提示 | 轻量候选，可复用动作；需要当前应用/会话活动依据 |
| I03 工作状态陪伴 | 开始处理时进入专注姿态，结束后简短回应，需要用户处理时提示 | 状态到动作的映射、提醒强度和冷却 | 推荐优先研究；Host 状态到原生层链路待验证 |
| I04 操作小彩蛋 | 新会话、切换会话、模型或工作区时，发生短促过渡、徽标变化或问候 | 开关、事件范围、动作、触发概率、冷却 | 推荐轻量候选；具体事件逐项验证，避免每点一次都打断 |
| I05 输入陪伴 | 在 DSH 输入时角色短暂看过来或跟着忙碌，停下后恢复 | 最小间隔、持续时长、静默模式 | 借鉴 Bongo Cat；只需活动信号，不需要记录输入内容或全局键盘钩子 |
| I06 专注与休息 | 用户主动开启计时，结束时角色伸懒腰并轻提醒 | 时长、提醒方式、暂停与勿扰 | 可由本地模块实现，是低成本实用候选 |
| I07 偶发性格彩蛋 | 空闲时低频打盹、伸懒腰，连续互动后有不同回应 | 出现概率、空闲阈值、动作池、安静时段 | 现有自主行为可扩展，避免新增大量素材和强制弹窗 |
| I08 模型对应外观 | 模型 A/B 使用不同角色、服饰、配色或徽标；无映射用默认鲸鱼娘 | 提供方/模型到资源组的映射、是否跟随、过渡 | 用户示例之一，属于候选；专属形象须有素材，并保留统一主题 |
| I09 工作区对应氛围 | 不同工作区使用不同强调色、角色小饰物或问候 | 工作区映射、覆盖优先级、默认回退 | 可选个性化；先验证活动工作区标识，不修改工作区业务配置 |
| I10 轻量熟悉感 | 本地记录少量互动偏好，改变问候或解锁小装饰 | 是否记录、重置、显示频率 | 后续候选，不引入饥饿惩罚、复杂经济或必须每日照顾 |
| I11 窗口栖息/攀爬 | 角色坐在窗口边、随窗口移动或攀爬 | 固定位置、允许窗口、是否跟随 | 视觉效果好，但需要窗口能力和对应动作；后续评估，不能直接移植 Windows 结论 |
| I12 角色快捷动作 | 点击角色菜单回到 DSH、暂停效果、开启专注、查看当前任务结果 | 菜单项、触发方式、反馈 | 可逐项复用已支持操作；涉及变更模型或任务时仍走宿主原有业务接口 |

建议正式首轮新增互动优先评估 **I03 工作状态陪伴＋I04 少量操作彩蛋**，配合 I01 现有互动完善；若宿主状态链路不具备，I06 本地专注提醒可作为候选替代。具体两项需结合接口和实际体验选择，不自动把全部候选拉入首版。

## 支撑各种小巧思的扩展方式

可把每个互动描述为：**触发时机＋场景条件＋反馈动作＋资源映射＋冷却/频率＋声音及勿扰设置**。这是模块内的受控配置规则，不要求首阶段建设任意脚本引擎。

### 可配置的范围

用户已确认希望可配置；下表为参数设计候选，不表示相关功能全部已入选或已有实现。

| 配置类别 | 用户可以调整的例子 | 约束 |
|---|---|---|
| 互动开关 | 欢迎回来、工作状态反馈、操作彩蛋等分别启停 | 只显示已提供的互动能力；关闭意图跨换肤保留 |
| 触发范围 | 当前会话、特定工作区、已验证的某类操作 | 从支持的事件与条件目录选择，不把任意事件名当已支持 |
| 动作与文字 | 对应动作、短气泡、是否显示回应 | 使用皮肤已提供资源与模块动作，不执行用户输入代码 |
| 模型/外观映射 | 为某个提供方与模型选择现有角色、服饰或配色 | 没有匹配用默认形象；只影响外观，不更改业务模型 |
| 频率与过渡 | 最小间隔、动作时长、出现概率、安静/活泼程度 | 模块提供类型、默认值、范围和资源预算约束 |
| 提醒与声音 | 提醒方式、音量、静音及勿扰 | 全局静音/关闭优先，按已接入模块提供 |

设置由三层共同作用：模块定义可用字段与实现，皮肤声明本套支持并允许调整的字段、默认值和资源，用户保存覆写。底座统一登记、校验协调和持久化，不理解每个具体玩法字段。新增已实现能力的组合可以改配置；新增动作种类或事件来源仍需要模块/适配实现。

设置界面建议先提供预设及常用项，再展开每项互动的详细参数；模型映射等适合专门的小编辑区。所选互动的运行参数属于皮肤使用设置，完整新建皮肤、资源打包和上传的制作工具继续后置。

### 每套皮肤的默认值与设置显示

每套皮肤为自己支持并展示的项带默认值，不要求每套实现所有玩法。设置页按当前皮肤的声明生成，不展示整个模块库的全部参数。

| 情况 | 设置页表现 | 运行处理 |
|---|---|---|
| 本套支持，默认值合法，能力可用 | 显示配置项，首次用本套默认值 | 用户覆写优先；返回本套恢复其覆写 |
| 本套未声明该互动能力 | 隐藏相关皮肤设置 | 不运行该互动；清理上一套效果，不借用上一套参数 |
| 本套有该互动，但某个参数固定、不开放调节 | 隐藏该参数的编辑控件 | 使用本套固定参数或模块兼容的内部参数，不继承上一套覆写 |
| 本套支持，但用户关闭 | 保留开启入口，详情可折叠或置灰 | 保留参数，尊重关闭，不自行重开 |
| 本套支持，但设备/模块版本不可用 | 显示原因和下一步 | 必需能力缺失阻止应用，可选能力按约定跳过 |
| 新格式声明可调项，却缺默认值或默认值非法 | 校验指出具体字段 | 修正前不应用；旧配置仅按明确迁移补齐 |
| 子项暂不适用，例如声音关闭时的音量 | 开关可见，子项按支持的条件折叠或置灰 | 保留子项值，不当作功能不支持 |

每项关联字段标识、展示名称、模块字段类型、合法默认值和可选范围；显示条件使用受支持的描述，不执行任意代码。作者可以固定内部参数，不将它们列成用户可调项。未开放某个参数不等于整个互动不能运行，是否具有该互动由皮肤的能力声明确定。

用户覆写高于本套默认值。模块内部默认只用于未暴露的内部参数和明确迁移，不掩盖新皮肤可调项缺默认值。全局关闭/静音仍优先，即使某套未使用该效果、相应设置被隐藏，偏好本身也保留。

“重置本套参数”恢复本套声明的默认值，保留全局关闭及授权。授权、当前状态、停止/恢复等通用管理入口独立于皮肤可调项，始终可访问。

- 可验证的事件由宿主适配提供；桌宠、气泡或局部动效由模块实现；皮肤包选择对应资源和参数。
- 规则跟随当前可见会话；后台会话不随意抢占同一个桌宠。真正需要后台完成提醒时，另有明确触发与节流。
- 模型映射只是多个例子之一。外观反馈不能擅自更换业务模型、提示词或权限。
- 连续状态更新合并处理，不逐 token 播动画；同类彩蛋有冷却，勿扰和用户关闭优先。
- 没有专属形象或动作时使用明确默认回退，不把资源缺失变成空白窗口。
- 需要新事件/新渲染能力时扩展对应模块或适配；只有新增公共能力才调整底座核心，沿用既定版本与生命周期规则。
