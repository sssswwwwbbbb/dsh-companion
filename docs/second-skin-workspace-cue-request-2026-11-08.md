# 工作区陪伴文案（`workspaceCues`）渲染反馈

**致**：主题盒子 / 陪伴插件开发者
**提交方**：第二套皮肤「黑焰」制作（无桌宠版）
**日期**：2026-11-08
**核对基线**：macOS arm64 · DSH `0.2.2-rc.1` · `dsh-plugin-companion 0.1.0-dev.46` · 皮肤 `black-flame 0.1.2`（`contentKey 87981d9a…`）

---

## 1. 现象

`manifest.workspaceCues` 声明的三条文案能正常触发、能正常显示，但**用户看不到**。

实测 `welcome`（「契约者，容器开着。火还在。」）：离开 DSH 18 秒后切回，窗口最底边的细条里出现一行无底色、单行、用正文色的文字，**2.8 秒后消失**。提交方在正常连续使用中从未注意过它，事后回看截图才发现。

截图：`designs/dsh-black-flame-v1/review/screenshots/workspace-cue-welcome.png`

## 2. 触发与渲染（来自 dev.46 源码）

| 项 | 现状 |
| --- | --- |
| 时长 | `setTimeout(clear, 2800)` —— 固定 2.8 秒，不可配 |
| 位置 | 窗口最底边细条，紧贴 Dock 上方；不避让输入区与状态栏 |
| 容器 | 无：没有底色、描边或内边距，只有文字 |
| 颜色 | 跟随正文色（皮肤 token），落在深色底上对比度尚可，但无托盘就容易被当成界面噪声 |
| 触发 | `welcome` 需离开 ≥15 s 再回来（冷却 60 s）；`session` / `workspace` 各冷却 4 s |
| 自定义 | 皮肤侧只有文案与开关，**没有样式或时长入口** |

代码位置（dev.46 `client.js`）：`observeWorkspaceCues()` 内 `timer=setTimeout(clear,2800)`；`show(next)=>currentCue=next` 只传递 `{kind,text}`，不携带样式信息。

## 3. 影响

- 作者按要求填了三条文案、设置页也有开关（`overrides` 里能看到用户确实拨过），但呈现上等于没有。
- 「设了但看不见」会让人误判为功能没生效，反过来增加排查成本。
- 与文档「长时间工作时以安静待机为默认，需要注意时才使用较明显的反馈」相冲突：现在所有 cue 都是同一强度，无法区分「轻提示」与「需要看见的提示」。

## 4. 期望（按优先级）

1. **给 cue 一个容器**：底色 + 1 px 描边 + 内边距 + 圆角，或直接复用现有 toast 样式（`--dsw-alias-toast-bg` / `--dsw-alias-toast-label`）。
2. **时长可配**：例如 `workspaceCues.*.seconds`，范围 1–8 秒，默认 3–4 秒。
3. **位置避开底边**：放到输入框上方居中或右下角，离窗口边缘留 16 px。
4. **样式 token 可选**：若能开放 2–3 个 token（前缀色、文字色），皮肤侧就能与本套视觉对齐。

## 5. 可接受的简化

先只做第 1 条（复用 toast 底色 + 内边距），时长维持 2.8 秒也行。这一条改完，可注意度就够用了。

## 6. 附带观察（未定性）

生成进行中点击侧栏会话行，界面未切换（AX 已确认点击落在该行）。同一时刻点「本套设置」子项则会被当作关掉页面。未确认是否为「生成中禁止切会话」的设计行为，仅作记录，不列入需求。

## 7. 复现

1. 应用 `black-flame 0.1.2`（或任一声明了 `workspaceCues` 的皮肤），在「本套设置」把「回到 DSH 时招呼」打开。
2. 切到别的应用 18 秒以上，再切回 DSH。
3. 观察窗口底部出现的文字与存续时间。
