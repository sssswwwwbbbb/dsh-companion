# DSH 皮肤底座：本地实现与隔离交付

日期：2026-11-03（Asia/Shanghai）。本轮按底座线职责完成 M0、M1，以及首套内容候选的首次 M2。没有提交、推送、部署、发布或替换用户真实 DSH/profile。

## 实现结果

1. 核对本机官方 DSH 0.2.1-rc.5 的 `theme.overrideTokens`、`theme/change`、`layout.panelInfo`、`shell.overlay` 与插件生命周期。颜色、背景只作用于会话面板；管理页面撤下，返回后恢复。未使用 DOM 私有类名作为扩展合同。
2. 新增 `packages/dsh-skin-core`：formatVersion 2 包、版本化模块、资源索引、合法默认值、条件显示、逐皮肤覆写、全局关闭、停止意图、异常回滚及单调操作代次。未知必需模块、非法默认或资源在准备时阻止；可选不可用独立报告。
3. 复用现有陪伴入口与授权，增加皮肤分区；皮肤管理期间原有冲突参数不可编辑。Host 单独写 skin-state.json；原生保留 legacy settings.json 的值，只更新自身位置等运行状态。皮肤参数不反写旧配置。
4. 页面回执必须对应当前页面实例、命令和代次；原生回执包含实际媒体就绪及内容摘要。超时后先提升代次，再清理/回滚，避免迟到成功重新显示。切到无桌宠皮肤或停止后释放视频媒体、暂停行为处理；缓存内容保留供回退。
5. 内容进入不可变摘要目录，作者编辑源目录不破坏旧内容恢复。原生 12 个动作可以使用逻辑资源，不局限于原角色绝对路径。v1 配置继续保留，迁移仅输出带来源的候选副本，不自动覆盖。
6. 官方插件移除时远程通道先卸载，不能再等待页面远程回执。该路径记录 `PLUGIN_SCOPE_DISPOSAL` 挂起边界，由官方客户端 ctx.effect disposer 释放页面效果；原生仍独立确认退出。重新启用必须由新页面握手才能恢复，不能把通道消失误记成用户主动停止。真实移除及重新启用已在隔离官方 UI 验证。

## 已解决的问题

- 处理 live pending 时不把正在执行的事务误当作崩溃恢复。
- 普通参数修改及重置在停止状态下只保存参数，不解除停止意图。
- 全局关闭会立即阻止正在进行的旧应用，防止候选快照重新打开已关闭模块。
- 失败/超时的旧操作在回滚前失效；原生迟到媒体 ready 不能重开已清理内容。
- 退出时卸载隐藏视频，旧 fetch 结果不能重新填充媒体；页面不重复传送已消费的大图片 payload。
- 应用级开场开关修改不会丢失当前皮肤的自定义动作资源。
- 官方停用/重新启用保留已确认选择，同时尊重用户单独保存的停止意图。
- 原生进程丢失不继续显示虚假的已就绪：可选桌宠标为不可用，必需桌宠停止整体效果，主动恢复成功后解除故障。

## 明确未验或未做

- 没有使用用户真实安装和 profile；隔离 renderer 是独立 Electron BrowserWindow 加载官方 Web 客户端，不等于用户真实桌面外壳。测试副本关闭 `dsh://open` 前台交接，因此前台唤醒未验。
- 长中文输入、切换保留和窄窗口完成检查；真实回复中的代码块、表格、滚动实操、错误/选中状态及全套对比度仍待业务画面验收。没有真实模型调用。
- 原生托盘点击、多显示器拖拽、复杂窗口关闭/最小化、长时间 CPU/内存基线未完整重验。本轮证明的是可见窗口、透明媒体、暂停和生命周期。
- 新扫描开场、工作完成信号、静态减少动态、字体/字号覆盖、外部壁纸兼容不在可用合同中。前几项设计提案仍记录在皮肤线需求；后续公共能力按模块扩展。
- Windows、其他 DSH 版本、第三方全局外观插件混用、正式签名公证与新版本分发未执行。官方叠加层自身的撤销不回写其他层，但未宣称所有组合兼容。
