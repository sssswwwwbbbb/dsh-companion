# 模型决定如何使用桌宠：接口复用与缺口

2026-11-03。回应用户“我们提供桌宠能力，让模型结合情景决定如何使用”的后续方向。这里核对接口与接入位置，供皮肤线收敛方案；没有注册新模型工具、发起真实模型调用或预建通用 Agent 平台。

## 当前可复用的执行能力

| 职责 | 当前真实实现 | 模型接入还缺什么 |
| --- | --- | --- |
| 动作 | CompanionService.action → Controller.action → 认证 bridge /action → main.mjs perform；沿用既有动作白名单、行为与媒体 | 面向模型的受控入口及本套允许动作列表；带当前皮肤/操作身份，不让迟到请求作用于新角色 |
| 说话/气泡 | main.mjs 内部 say、sendState；pet.mjs 用 textContent 呈现纯文本 | 当前 action 的文案是内置固定句，没有公开 say(text) 远程能力；动态短句的字段、长度、关闭及冷却应由相关模块定义。当前没有声音资源或语音能力 |
| 跟随/移动 | 已有 followMouse、本地 walkTo、边界 clamp 和原生窗口 | R3 已验证跟随开关；模型给目标位置不是已有外部 API。若场景确需移动，复用原生边界与状态机，另定受控参数 |
| 停止/切换/恢复 | Host 唯一协调、generation、独立停止锁、当前页面确认、统一授权 | 模型请求复用这些失效与授权机制；执行前后检查当前操作，停止时取消模型请求，不再创建第二套停止系统 |
| 资源与设置 | 当前皮肤目录/摘要缓存、模块字段描述、逐套覆写和全局关闭 | 未来 decision/feedback 类模块使用相同合同。当前没有这些模块，不把设计字段放入 R3 包 |

第一套新角色拟用四姿态，首轮动画先做 idle/react；当前 M0 自定义 animations 要求 12 槽。动作可用子集与缺资源回退归 pet 模块演进，不能因全局白名单有动作名就声称新角色已支持。先等实际资源与场景收敛，不用静帧视频补槽冒充动画。

## 官方宿主接口已核对

目标全部为已安装官方 DSH `0.2.1-rc.5`；本轮只读 SDK，不读取用户会话。来源、许可、摘要和行号在 `reports/skin-foundation-r3-2026-11-03/interface-audit.json`。

| 官方接口 | 来源证据 | 可复用部分与条件 |
| --- | --- | --- |
| ctx.tools.register(defineTool(...)) | dsh-tools README.zh.md 工具注册段 | 类型化能力、JSON 参数/结果、工具执行与现有策略；执行体收到 exec.signal，可复用取消。工具注册会进入模型的可见集合，需按开启状态与合适作用域提供 |
| ctx.tools.restrict / guard | 同包“按 agent 限制工具/对调用实施策略” | 复用官方作用域和执行策略，不另造权限框架。当前仍需验证工具调用来源会话与前台范围的实际关联 |
| ctx.llm.prepareCall(config, signal, configure?) / stream(options) | dsh-llm README.zh.md L50、L63、L84 | 如确需会话外辅助决策，复用已配置路由、模型能力、调用默认和取消；输入须满足宿主可记录/可重建要求，不另读密钥或建代理服务 |
| ctx.sessionController / Client session namespace | dsh-api-session-controller README.zh.md L13、L36 | 按会话寻址、统一访问控制与会话操作；具体当前会话和运行结果的投影接入还需要小型受控验证 |
| ctx.modelDirectories、session.models / selectModel | dsh-client-ui-model-selection README.zh.md L76、L97 | 复用真实提供方/模型目录与会话选择。选择影响后续请求，已运行步骤保留其快照，不能只根据界面显示名推断调用身份 |
| Client Session hooks / 运行状态投影 | dsh-client-ui-session README.zh.md L13、L27 | 有官方状态与访问接口；“completed/needs-user”目前仍是原型标签，需要映射真实状态来源与会话边界后再使用 |

这些是源码确认的复用入口，尚不是本插件已接入能力。文档使用的 say/act/decision 是职责描述，不代表新增远程方法已可调用。

## 两种接入场景的差别

- **当前工作会话里的模型调用能力**：优先考虑注册少量桌宠工具，由已有 DSH Agent 自行选择是否使用，复用其模型与上下文，不必另外创建一套模型循环。仍需定型允许动作、文案、人设说明、配置开关及当前会话范围。
- **会话外主动陪伴决策**：只有产品方案明确需要时，再用 ctx.llm 的辅助调用接缝；情景输入、触发频率、模型选择、超时/预算和记忆范围需要先收敛。动画、移动和时序继续本地执行，不逐帧调用模型。已有标题辅助调用包可作取消/上限处理参考，其用途与记录类型属于标题服务，不能直接当桌宠接口。

本轮没有替皮肤线选择全部模式。最小后续闭环宜是一种已确认情景 → 模型选择一个允许动作/短句 → 现有执行端执行 → 停止或切换后旧结果失效，并保留简明的本地回退。

## 需皮肤线给出的下一步输入

1. 当前会话工具使用，还是需要额外主动陪伴；本套实际资源支持哪些能力。
2. 给模型的情景字段和人设、主动程度、默认开关及可读上下文范围。
3. 短句/动作的频率、气泡关闭和失败回退；新角色静态与动画资源的可用范围。

这些通过共享 integration-needs.md 收敛即可。主控已经通过的停止/请求顺序不重做；基础配置也不因新增方向撤销。编辑器、上传、市场、外部壁纸继续后置。
