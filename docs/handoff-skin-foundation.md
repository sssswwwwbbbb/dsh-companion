## 当前确定的产品规则

- 一个插件入口、一份授权，Mac ARM 优先。首轮组合为主工作区主题＋现有桌宠；A 仅主题，B 主题＋桌宠用于模块差异验证。
- 首套视觉参考为档案暖白＋鲸鱼娘扫描睁眼。具体美术和资源由皮肤线维护，底座不写入这些主题特例。
- 新增轻量互动且可配置。每套皮肤声明支持项并带默认值；不支持的项隐藏，用户关闭和能力不可用区分。模型映射是例子，不是本轮所有模型都要制作专属角色。
- 外部壁纸插件/Wallpaper Engine 格式兼容排除，自带背景保留。开源制作、自制编辑器、上传与市场后置。

## 任务顺序

按用户补充执行 [开源复用原则](parallel-development-2026-11-03.md)：优先复用本项目、官方宿主能力和合适的开源实现；新增通用能力前检查可复用方案，只自研必要的适配与业务差异，并在本线报告保留来源、版本、采用或不采用的理由。

1. 只读核对官方目标版本接口和现有控制器/原生实现，输出能力矩阵，区分证据与假设。
2. 维护共享合同，定型实际字段、模块接口、资源解析、默认值/显示/覆写/兼容规则，提供最小可执行样例。先完成 M0，不能让皮肤线猜字段。
3. 在 `packages/dsh-skin-core/` 实现最小核心，优先新增独立模块，复用授权与桌面能力。不要建设通用脚本引擎、独立模块商店或另一套宿主。
4. 按合同适配页面主题与现有原生桌宠，贯通唯一协调、操作代次、实际就绪、退出、失败恢复和停止意图。保护 dev.11 的正常重开与运行中重新启用两条启动行为。
5. 用 A/B 及受控异常样例检查默认值、设置显示、资源隔离、迁移边界、迟到响应和清理；在隔离官方宿主中检验可见效果和基本操作，分别记录未做的实机项目。
6. 在阶段边界读取皮肤线的 `designs/dsh-skin-v1/integration-needs.md`，逐项回应可用、需扩展、不可用；视觉合同变化只在确有公共需求时改核心。

## 写入职责与边界

主要写入 `packages/dsh-skin-core/`、`docs/skin-foundation/`、`reports/skin-foundation/` 和共享合同。必要时修改 `packages/dsh-companion/`、`runtime-src/` 的接入代码，修改前查看差异并确认没有其他工作线正在改同一文件。

不改 `designs/dsh-skin-v1/`、首套美术、既有授权密钥或服务数据，不重写总体方案/评审。皮肤需求通过共享文件交接，不需要向其他对话发送消息。

本地与隔离验证在本轮范围；不替换用户真实 DSH 安装、不修改其 profile、不部署服务或发布。不得因这些后续阶段尚未执行而停止可独立完成的本地工作。

共享工作目录下不自行 commit/merge/push、不操作公共暂存区，保留他人修改。可读 Git 状态/差异并完整记录自己改动的文件。
