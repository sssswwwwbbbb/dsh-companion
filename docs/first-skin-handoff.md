# 第一套 DSH 皮肤：新对话接手

当前目的：先讨论皮肤范围与功能清单，再确定方案和素材，最后进入实现。不要根据候选列表直接扩展功能。

## 用户已经确认

- 产品是一整套 DSH 皮肤，不能仅按启动动画与桌宠理解。
- 希望每套皮肤可以通过配置切换，插件是用户的统一入口；授权使用一份激活码。
- Mac Apple 芯片优先验证，之后适配 Windows 与官方长期有效的 DSH 版本。
- 尽量复用开源组件，保持轻量、简单；角色素材后续可由用户提供。
- 第一套皮肤的主题、角色、具体覆盖面和功能清单尚未确定，先讨论。

## 首轮讨论应解决

1. “一整套皮肤”在用户心里的覆盖边界：哪些界面、动画、桌宠、交互需要成为统一体验。
2. 第一套的主题与参考、已有素材，以及哪些候选能力属于首版、后续或不做。
3. 哪些改变只涉及外观，哪些会新增行为与功能；各模块是否需要独立开关。

主界面、侧栏、消息、输入框、弹层、背景、字体、图标、声音、启动动画和桌宠都是讨论候选，不能当作已确认需求。首轮优先问少量关键问题，按用户的回答逐步收敛。

## 流程技能

项目技能：`skills/dsh-skin-development/SKILL.md`。已经在本机 Codex 技能目录创建指向它的发现链接，可使用 `$dsh-skin-development`。

技能只规定讨论、能力核对、素材、配置、实现、验收与交付的通用流程，不提前确定首套功能。范围和实际做法明确后再完善技能；不需要现在就发明通用皮肤引擎或新授权系统。
