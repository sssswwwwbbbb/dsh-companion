## 结论

- **视觉规范、关键稿及角色候选的材料交付通过。** 五个视图、明暗职责、密集阅读场景、角色对照、互动时序和来源记录已形成可检查产物，当前方向可以保留并继续迭代。

- **运行版、真实客户端未通过本轮验收。** 当前运行内容仍为 R1 技术包，未包含 R2 新角色。新角色的逐帧动作、状态资源、脚底锚点和原生接入仍待制作；既有 R1 宿主记录不能覆盖这些工作。
- 角色的全身服装是设计延伸，本轮可作为候选，不记为用户已确认的最终美术设定。

## 必须修订的三项

### D-R2-01｜P2：能力不可用状态没有贯穿演示页

复现：皮肤设置选择“能力不可用”，桌宠与反馈开关禁用并说明设备不可用；进入“启动与桌宠”，仍出现可点击角色，且实际样式为 `unified-pet has-motion`、`animation-name: companion-breathe`。

源码：`designs/dsh-skin-v1/app.jsx` 中 `scenario` 没有传给 `FlowScreen`；`screens.jsx` 的 `disabledPet` 仅判断 `stopped || !config.pet`。事件处理会拦截动作，但呈现层仍表示桌宠正常可用。

证据：[设置状态](../reports/first-skin-acceptance-2026-11-03/02-unavailable-settings.png)、[仍显示角色的演示页](../reports/first-skin-acceptance-2026-11-03/01-unavailable-still-active.png)、browser-checks 的 UI02。

修订要求：演示页消费同一份有效能力状态；能力不可用时显示原因和保留参数的说明，停止实际角色表演。角色对照页的静态审稿素材可保留，但要与运行演示区分。恢复能力后保留用户参数和关闭意图。

### D-R2-02｜P2：“需要处理”的静态状态错误依赖气泡开关

复现：默认状态关闭“显示短气泡”，进入演示页点击“需要处理”。日志声称“静态提示”，角色却继续 `companion-breathe`，没有静态提示。

源码：`app.jsx` 的 `needFeedback()` 在气泡关闭时传空文本；`screens.jsx` 用 `action === 'idle' && !!bubble` 推断 `staticPose`。业务反馈层级和表演状态因此被一个展示偏好间接改变。

证据：[无气泡反例](../reports/first-skin-acceptance-2026-11-03/03-needs-user-bubbles-off.png)、browser-checks 的 UI03（包含实际计算样式与日志）。

修订要求：明确保存反馈状态/优先级，独立决定静态表现；关闭可选气泡不能恢复本应冻结的动作。原始会话的需处理状态仍保留。复验气泡开/关 × 减少动态开/关 × 庆祝被打断，以及停止、恢复和状态解除。

### D-R2-03｜高优先级设计缺口：当前配置深度不足以作为正式首版定稿

实际运行包只有两个皮肤专属公开参数：`theme.backgroundOpacity` 和 `pet.size`。通用模块开关及停止/恢复另计。原型有 11 个设计字段，但包含大量开关和少量枚举；它们还不是运行能力。

现有合同已支持 `pet.profile`、`pet.autonomous`、`pet.followMouse`，当前包将它们固定在 config。将其改为本套公开设置并提供默认值，在内存验证中可解析出合法控件和用户覆写，不需要先重写协调、存储或资源底座。这项证据只证明合同可表达，不代替行为实测。

应补一份**首版配置矩阵与对应设置稿**，逐项标明“正式首版 / 后续 / 不做 / 待验证”、皮肤默认值、允许范围、资源与能力依赖、显示条件、用户覆写、缺失回退，以及实际接入状态。下面为修订建议，不把所有候选自动升级为已承诺首版功能：

| 配置组 | 建议让用户可调的内容 | 当前状态 / 主要归属 |
|---|---|---|
| 配色与表面 | 本套配色预设、强调色方案；文字/表面调整受可读性约束 | R1 token 固定；皮肤提供方案，主题模块提供可选能力 |
| 自带背景 | 本套背景选择、浓度、适用区域与显示方式 | 仅浓度已公开；不扩展外部 Wallpaper Engine 兼容 |
| 桌宠行为 | 大小、行为风格、自主活动、跟随鼠标 | 后三项合同已有但本套固定；先明确并补受控行为检查 |
| 角色与服装 | 从本套真实提供的形象/服装变体中选择 | 当前只有同一角色四姿态；不能把动作当成四种形象或制作不存在的选项 |
| 点击反馈 | 开关、可用动作、可选气泡文案、重复触发策略 | 原型仅开关及固定回应；需资源和模块参数扩展 |
| 工作反馈 | 各事件开关、动作、气泡、冷却与当前会话范围 | 有模拟稿；事件源未接入，需明确绑定和失效规则 |
| 开场 | 本套开场方案、启停、播放条件及跳过策略 | 新扫描仅参考；复用原有生命周期，模块验证后接入 |
| 模型或状态映射 | 在支持事件的前提下绑定形象或动作，未映射时回本套默认 | 用户举过的可配置方向；真实信号与资源都尚未就绪 |
| 动态与干扰 | 减少动态、活动频率、反馈强度及无声体验 | 原型有减少动态；实际静态能力仍待模块扩展 |

界面先分“常用”和“更多”，有映射或文案列表时使用适合的编辑区。每套只暴露自己支持的项，均带合法默认值；用户改动保存为该皮肤的覆写，不直接修改皮肤原文件。不支持则隐藏，可用但关闭则保留开启入口，不可用则解释原因。重置不清全局停止、静音和授权。

增加已有模块参数时在模块内演进；新增模型/任务事件、角色变体或开场能力时扩展对应模块及版本合同。公共协调、资源、存储和撤销机制继续复用。不要为了多几个设置，允许皮肤执行任意脚本。

制作编辑器、自制皮肤上传和市场继续后置。本次要求的是用户可调范围及未来作者可声明范围的设计清楚，不提前实现完整制作平台。
