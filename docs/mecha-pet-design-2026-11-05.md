# 机械姬桌宠：可行性判断与素材清单

2026-11-05，Asia/Shanghai。用户方向：设计一个机械姬桌宠，由自己设计动作，大模型结合情景自主决定她做什么。本文只做可行性判断与素材规划，不改运行合同，不发起模型请求，不含新角色美术。

## 结论：可行，缺口在"主动触发"和"语义—素材对齐"

机制上已经到位，不需要新架构：

- 底座已有 `petInteract({text, trigger})`、`actionDescriptions`（动作 ID → 1–120 字语义）、`persona`、`allowSpeech/allowActions`、30 秒截止与失败回退，模型只返回 `{speech, action}`。见 [M3 桌宠互动合同](skin-foundation/pet-interaction-contract-m3.md)。
- 皮肤模块 v2 允许声明**真实动作子集**（必须含 idle），不必先凑满 12 槽；只有已声明且有媒体的动作进入运行清单。
- 素材管线已有：母版 → 关键姿势 → 视频 → RGBA 去背 → WebM VP9 alpha → `asset-manifest.json` 锚点登记，见 [v3 素材交接](../designs/dsh-skin-assets-v3/README.md)。

真正缺的两件事：

1. **主动触发**。当前所有互动都由 `input`/`click` 发起，她不会自己动。要"自主活动"，必须补一个定时器 + 情景快照，走同一条 `petInteract` 通道，并配预算、冷却、勿扰时段。这一层属于新能力，按 [模型决策增量方案](first-skin-design/llm-capability-direction-2026-11-03.md) 的顺序单独收敛。
2. **动作语义与素材的一一对应**。模型只能选清单里有的动作。清单写多了，她一选就播不出来；清单写少了，她觉得她"什么都不会"。素材规划本质上是在规划这份清单。

## 一、机制：模型做选择题，本地做执行

```text
定时器/点击 → 情景快照（人设+时间+状态+近5次动作+可用动作） 
→ 模型返回 {speech, action} → 白名单与前置条件校验 → 本地状态机播放 
→ 实际结果回写历史 → 下一次上下文
```

三条铁律，缺一条就会退化成"随机播放器"：

1. 模型只输出清单内的动作 id，清单外一律回落到 idle。不接受自由文本动作名。
2. 模型不控制坐标、时序、播放与打断。移动、边界、拖拽、睡眠优先级归本地状态机。
3. 每次调用有边界：冷却（建议 ≥90 秒）、每小时上限（建议 20–40 次）、超时 3–5 秒回落本地行为、全局停止后迟到结果作废。

给模型的上下文决定"自主感"的上限。建议快照字段：人设、当前时间、是否整点/深夜、最近 5 次动作 id 与结果、用户鼠标是否在附近、DSH 工作态（可选）、可用动作清单及一句话描述。

## 二、先写语义表，再画素材

这份表就是 `actionDescriptions` 的来源，也是美术的排期依据。**表里没有素材的动作不写进清单。**

| id | 给模型看的一句语义 | 时长 | 循环 | 可被打断 | 前置条件 | 依赖部件/道具 |
| --- | --- | --- | --- | --- | --- | --- |
| `idle` | 安静站着待机，偶尔呼吸起伏 | 2.5s | 是 | 是 | 无 | 无 |
| `idle_look` | 东张西望，注意到周围变化 | 3s | 是 | 是 | 无 | 无 |
| `idle_fidget` | 百无聊赖地整理袖口或调整天线 | 3s | 否 | 是 | 无 | 天线（若分层） |
| `walk` | 走到屏幕另一处 | 1s/循环 | 是 | 是 | 未在拖拽 | 无 |
| `run` | 小跑着过去 | 0.72s/循环 | 是 | 是 | 同上 | 无 |
| `react_touch` | 被点击或摸到时的回应 | 1.8s | 否 | 是 | 无 | 无 |
| `greet` | 主动打招呼，注意到你回来了 | 2.6s | 否 | 是 | 长时间无互动后 | 无 |
| `drag_hold` | 被拎起来悬空 | 循环 | 是 | 否 | 拖拽中 | 无 |
| `drop_land` | 落到桌面后站稳 | 0.8s | 否 | 是 | 刚落下 | 无 |
| `charge_sleep` | 进入充电休眠，指示灯转暗 | 循环 | 是 | 是 | 深夜/长时间空闲 | 充电线、发光件 |
| `wake` | 从休眠中苏醒，指示灯亮起 | 1.5s | 否 | 是 | 刚从 charge_sleep 出来 | 发光件 |
| `glitch` | 短暂故障，画面抖动后恢复 | 1.2s | 否 | 是 | 低概率或被打断过多 | 故障贴图 |
| `read_book` | 拿出书来读，视线落在书页 | 6–10s | 是 | 是 | 未在移动 | 书、双手使用动作 |
| `drink_tea` | 端起杯子喝一口 | 4s | 否 | 是 | 未在移动 | 杯、握柄手型 |

前 8 条是 MVP，后 5 条是第二期。`glitch`、`charge_sleep`、`wake` 是机械姬相对人类角色的差异化动作，优先做，因为它们几乎撑起了"她是机器"的全部观感。

## 三、素材清单，分五层

### L0 身份母版（1 套，必须最先定）

| 项 | 规格 | 用途 |
| --- | --- | --- |
| 全身正面母版 | ≥2048px 高，透明或纯色可去背，全身入画不裁切 | 所有动作的生成源 |
| 背面/侧身补图 | 各 1 张 | 攀爬、侧躺、转身 |
| 表情集 | 眼（正常/半闭/关机/故障雪花）、嘴、腮红各 2–3 态 | 独立图层，程序切换 |
| 拆件 | 天线、耳机、机械关节、发光线、背部接口、尾/悬浮环 | 独立 PNG，程序驱动旋转/浮动 |
| 色卡与材质说明 | 主色/辅色/发光色 + 金属度、粗糙度、描边宽度 | 生成时的一致性约束 |
| 识别锚点 | 3 个（头饰形状、胸甲开孔、配色比例） | 每次生成写死在提示词里 |
| 几何锚点 | 脚线、命中区 | 接入原生拟合 |

### L1 动作素材（12–15 段循环/单次）

每段要求：能接回 idle；首末帧不要求字节一致，但要有 90ms 淡入；同框同锚点，不因姿态改变人物大小。

### L2 道具与场景

书、杯、坐垫、充电线/电池仓、数据屏、桌面投影阴影、拖动时的"被拎起"变形层。道具要能随动作出现与消失，不能常驻脚边。

### L3 声音

点击音、脚步、伺服/液压声、休眠电流声、可选语音。**声音会显著增加成本与授权复杂度，建议第二期再定。**

### L4 文本资产（最容易被低估）

- `persona`（300–800 字）：她是什么型号、为什么在桌面、对使用者什么态度、口头禅边界。
- 动作语义 12–15 条（就是第二节的表），每条 1–120 字，用"她能做什么"而不是"动画叫什么"。
- 兜底 `localReply`（≤120 字）：关掉智能、断网、模型超时时说的话。
- 勿扰与拒绝策略：深夜、开会、全屏时该沉默还是该凑近看。

### L5 配置

动作 manifest（id、文件、时长、循环、可打断、前置、锚点）、决策策略（频率/时段/预算）、状态输出（电量、亲密度）。**注意：界面上显示出来的状态必须有真实来源，否则就是假 UI。**

## 四、机械姬特有的四个技术坑

1. **刚体部件不适合视频形变**。装甲、关节、天线在 image-to-video 里会"融化"、抖动、互相穿插。方案：身体用视频，刚性部件单独图层用程序做旋转与位移；或者直接上 Spine/Live2D 分层。后者对机械姬更自然，但要重做管线，成本要先算清。
2. **发光件必须单独一层**。眼睛、胸口、线缆发光用叠加（add）混合层，才能做"开机、断电、故障、低电量"这四种状态，这四种状态比任何动作都更能表达"她是机器"。
3. **表情比动作便宜**。机械姬的脸往往是屏幕或单眼，换 2–3 张眼睛贴图 + 局部发光，就能产出大量情绪，性价比远高于逐帧做动作。
4. **硬表面一致性最容易崩**。线条、分件、配色比例每次生成都会漂。固定三个识别点写进提示词，每次生成都以母版为参考图，不沿用上一张动作图继续生成。

## 五、生产管线（复用现有）

```text
母版 → 关键姿势图（Seedream 2K，参考母版）→ 即梦生成视频 
→ 去背 → WebM VP9 alpha → manifest 登记 → 原生拟合脚线/锚点
```

规范沿用当前母版：499×1024 定稿、24fps、VP9 有损（首末帧不承诺字节一致）、单段 ≤16MiB、总资源 ≤128MiB、WebM ≤32 个。每段动作都要能"从任何状态进入，并回到 idle"。

## 六、MVP 四步

| 步骤 | 产出 | 判断标准 |
| --- | --- | --- |
| 1（1 天） | 身份母版 + 第二节语义表 | 表里 8 条动作都能一句话说清"她为什么做" |
| 2（3–5 天） | idle 变体 2 段、react、walk | 不看提示词也能认出是同一个人 |
| 3（2 天） | 接模型决策，只开放 3 个动作 | 连续用一天，她有没有让你觉得烦 |
| 4 | 按真实使用补动作 | 不做"先画 20 个再说" |

第三天的结论比美术质量更重要：**动作多但风格不统一，比动作少更像 bug。**

## 七、可观察验收

- 连续 2 小时，同一动作不连续重复超过 3 次。
- 拖动、停用、换肤、全局停止后，没有残留动作与残留道具。
- 模型超时、断网、模型无路由时，本地行为照常，且 `localReply` 出现。
- 每个动作都能从任意状态进入并回到 `idle`，接缝处不跳大小、不跳位置。
- 深夜勿扰时段命中时，她不说话也不移动。

## 八、需要拍板的五件事

1. 平台：Mac / Windows 是否都要各自验收。
2. 动作预算：MVP 8 条够用，还是直接冲 20 条。
3. 语音：要不要，什么时候要。
4. 模型：跟 DSH 当前默认模型，还是指定小模型，还是本地模型。
5. 自主程度：安静型（一天动十几次）还是存在感型（一直在旁边忙）。

## 九、视觉与人格方向：科研企业风（原创化）

2026-11-05 追加。用户确认机械姬整体走「科研企业」气质。参考对象是《明日方舟》莱茵生命的**类型语言**，不是它的表达：标志、字样、具体角色造型与配色组合都不使用，只保留"冷白、临床、企业化、非人但被维护"的抽象气质。判定标准：换掉所有文字与标志后，不会让人说"这是方舟的谁"。

### 9.1 设计命题

**她不是战斗机器人，是企业资产。** 这一句决定全部取舍，推论三条：

- 干净：没有战斗损伤、没有外挂武器、没有发光符文。她的复杂度来自结构，不来自装饰。
- 编号化：型号、批次、维护状态是可读的，不是装饰图案。
- 被维护而非被爱：关节有保养痕迹，工牌有更换过的位置，语气是"记录"而不是"撒娇"。

桌宠场景里她的身份就很自然：**驻留在使用者桌面上的研究单元**，有授权范围，有电量，有维护周期。

### 9.2 大形状：先定这五块，再谈细节

| 部位 | 结构 | 作用 |
| --- | --- | --- |
| 头 | 圆润封闭头壳，正面一条横向观测窗；后脑一对散热鳍与接口 | 观测窗是脸，是最大识别面 |
| 肩胸 | 短斗篷式肩甲（实验室外套的结构化变体），胸口纵向开孔露出内部结构 | 给"被打开过"的叙事 |
| 腰 | 束腰收口，左肩一条工牌带 | 唯一的织物软元素，打破全硬表面 |
| 下肢 | 直筒机械腿，分节脚踝，脚是设备支脚而非高跟鞋 | 站立稳定，走路循环好做 |
| 非对称 | 三选一：左肩工牌带 / 右侧线缆 / 单侧耳侧模块 | 三样全上就变成装饰堆砌 |

### 9.3 色彩：按面积分配，不按喜好

| 面积 | 角色 | 建议值 | 规则 |
| --- | --- | --- | --- |
| 60% | 暖白与冷灰 | `#F1F2EF` / `#C7CDD2` | 纯白在深色桌面上会"死"，必须用暖白与冷灰拉开层次 |
| 25% | 石墨 | `#2B3138` | 关节、内衬、阴影，负责"重"的那一半 |
| 10% | 企业青 | `#3FB6C8` / `#56D6E0` | 只用于发光与标识，超过 12% 会显廉价 |
| 5% | 琥珀警示 | `#E08A3C` | 只用于故障、低电、警告，且必须有真实状态来源 |

禁用：紫粉渐变、彩虹霓虹、金色描边、大面积半透明。

### 9.4 材质五层，不多不少

哑光工程塑料（主体）、阳极氧化铝（关节与边框）、抛光玻璃（观测窗）、织带（工牌带与束腰）、发光亚克力（胸腔与线缆）。第六种材质就是"开始堆料"的信号。

### 9.5 三个识别锚点

① 观测窗的横向比例与两端收角　② 胸口纵向开孔与内部结构　③ 左肩工牌带

判定方法：把她的图缩到 64px 高，这三点还能认出来，锚点才算成立。每次生成都写进提示词，不以"参考上一张"代替。

### 9.6 企业标识系统（原创）

- 抽象标志：由观测窗形状与胸口开孔衍生一个几何字符，单色可用，不要写实徽章。
- 工牌：姓名位写型号，条码位写批次，不用真实公司名。
- 命名规则：`单元-07`、`原型-03`、`维护中`；不堆英文缩写。
- 编号出现在三处即可：工牌、设置页标题、开场第一句台词。

### 9.7 persona 草案（非人感，不讨好）

三条原则：报告式短句；不称"主人"，用"使用者"或省略；情绪用状态词代替形容词。先写 400 字，合同上限 2000 字。

> 「单元-07 已就绪。当前电量 82%，维护周期还剩 6 天。」
> 「检测到接触。已记录。」
> 「你的用时已超出常规区间。需要我进入静默吗？」
> 「自检异常。正在恢复——恢复完成。刚才的记录我没有保留。」

### 9.8 动作语义的企业口吻版

第二节那张表口吻偏日常，二者选一。**模型看到的就是这张表的措辞，措辞换掉，她的人格就换掉了**——这是全套素材里最便宜的一次改造。

| id | 日常口吻 | 企业口吻（推荐） |
| --- | --- | --- |
| `idle` | 安静站着待机 | 维持待机，周期性自检 |
| `walk` | 走到屏幕另一处 | 移动至指定坐标 |
| `react_touch` | 被点击时的回应 | 检测到接触，记录 |
| `greet` | 主动打招呼 | 使用者返回，建立会话 |
| `charge_sleep` | 进入充电休眠 | 进入低功耗维护模式 |
| `wake` | 从休眠中苏醒 | 维护完成，恢复运行 |
| `glitch` | 短暂故障 | 自检异常，正在恢复 |
| `read_book` | 拿出书来读 | 调阅纸质档案 |

### 9.9 版权红线

可用：白 + 青的科研企业类型语言、工牌、编号、临床语气、冷白配色逻辑。这些都是类型惯例，不是版权表达。

不可用：莱茵生命的标志与字样、塞雷娅／白面鸮等角色的具体造型与配色组合、方舟专有名词（源石、哥伦比亚、莱茵生命本身）出现在产品界面或宣传里。

### 9.10 对素材清单的增量

- 企业标识系统：抽象标志 1 个（单色 + 反白两版）、工牌 1 张、编号字体规则。
- 观测窗表情集：待机、注意、记录、困惑、低电、故障，共 6 态（叠加层，不重画身体）。
- 琥珀警示层：低电与故障时替换青色发光，需与真实电量状态绑定。
- 维护态拆件：背部接口、线缆、检修盖板，用于 `charge_sleep` 与 `wake`。

### 9.11 母版提示词骨架

沿用现有生成习惯：以母版为参考图、纯浅暖灰背景、单人物全身入画、不裁切。

```text
科研企业风格的机械少女全身设定图，正面站立，三分之四机位。圆润封闭式头壳，
正面一条横向观测窗作为面部，不含人类五官；后脑一对散热鳍与接口。短斗篷式肩甲，
胸口纵向开孔露出内部结构；左肩白色工牌带。直筒机械腿，分节脚踝，设备式支脚。
配色：暖白与冷灰为主体，石墨色关节与内衬，青色发光仅用于观测窗、胸腔与线缆，
面积不超过一成。材质：哑光工程塑料、阳极氧化铝、抛光玻璃、织带。干净、克制、
无战斗损伤、无外挂武器。纯浅暖灰背景，单人全身入画，四周留空，不裁切。
```

## 十、一整套主题：素材清单与预算

2026-11-05 追加。范围从「桌宠」扩到「整套主题」。先分层，否则会做出一批进不了包的东西。

### 10.1 两层交付，别混在一起

| 层 | 内容 | 约束 | 谁消费 |
| --- | --- | --- | --- |
| A 皮肤包 | `theme` + `startup` + `pet` 三个模块 | 硬预算：资源 ≤32 个、总量 ≤128MiB、单个图像 ≤8MiB、单个 WebM ≤16MiB | 随皮肤装进客户端 |
| B 品牌层 | 工作台重绘、图标系统、管理页、商店封面、宣传图 | 不受 32 位限制，但也不走皮肤合同 | 产品与营销 |

产品意义上的「整套主题」是 A + B，但**只有 A 能随皮肤分发**。B 要做，得按产品工作量另算。

### 10.2 32 个资源位怎么花

| 模块 | 素材 | 数量 | 格式 | 备注 |
| --- | --- | --- | --- | --- |
| pet | 角色母版图集 | 1 | PNG | 含肖像、头像、道具分格，一图多用 |
| pet | 动作 | 8 | WebM | 0.1–60 秒，每个都要含 idle |
| startup | poster | 1 | PNG | 必需，开场静态定调图 |
| startup | 开场视频 | 1 | WebM | 可选，1–15 秒，**必须无音轨** |
| theme | 背景 | 1 | PNG/JPEG/WebP | 不透明度上限 15%，实际只有 4% |
| theme | 皮肤封面 | 1 | PNG | 管理页卡片用 |
| 品牌 | 抽象标志 | 1 | PNG | 单色，两版塞进同一张 |
| | 小计 | 14 | | 留 18 位给二期动作、多语言与更新 |

### 10.3 每个模块到底要什么

- **theme**：60–80 个颜色 token × 明暗两套（不是图片），背景 1 张，可选一张装饰纹理。token 一旦定，所有界面的颜色都不用再改。
- **startup**：poster 必需；video 可选且必须无音轨；配 `greeting` / `subtitle` 文案与秒数（1–15 秒）。
- **pet**：母版图集、8 段动作、肖像、头像、道具、锚点、动作语义表、persona、`localReply`。
- **管理页 / 设置**：皮肤封面、缩略图、状态与授权文案（纯文本，不出图）。
- **每个资源都要能填** `source` 与 `license`：AI 生成的写清模型、提示词与生成日期，否则后面无法交付。

### 10.4 最容易做错的三件事

1. **给主题背景画大图。** 合同里背景不透明度上限 15%，内部只有 4%。画得再细也被压成一层几乎看不见的纹理。用 CSS 网格、扫描线、等高线，把预算留给角色和开场。
2. **把图标一张张切。** 一个图集解决；能用程序画的（网格、发光描边、进度条、扫描线）就不要出图，既省额度又不会糊。
3. **把开场当附属品。** 开场是用户唯一会完整看三秒的画面，是整套主题的定调点。poster 与 video 的投入应排在角色之后、其他一切之前。

### 10.5 跨模块素材类型总表

| 类型 | 位置 | 数量级 | 备注 |
| --- | --- | --- | --- |
| 角色 | pet | 1 套母版 | 所有动作的生成源 |
| 动效 | pet / startup | 8–10 段 | WebM alpha，单段 ≤16MiB |
| 界面图形 | theme / 管理页 | 1 个图集 | 图标、装饰、状态条 |
| 颜色 | theme | 60–80 token | 全部用 token，不写死色值 |
| 文本 | 全模块 | 约 2000 字 | persona、语义、兜底、开场字幕 |
| 声音 | 无 | 0 | 合同暂无声音能力，开场视频还要求无音轨 |
| 品牌 | 包内 + 营销 | 1 标志 + N 张 | 包内 1 张，其余进品牌层 |

声音这一格是 0，不是遗漏：合同没有声音通道，开场视频还明确要求无音轨。等真有语音能力时再立项，别提前配音。

### 10.6 生产顺序（有依赖关系）

```text
色卡与 token → 角色母版 → 动作 → 开场 poster/video → 工作台重绘 → 管理页 → 营销图
```

- 色卡先行：tokens 定了，界面颜色不再返工。
- 母版先于动作：动作可以并行，但都依赖母版；不沿用上一张动作图继续生成。
- 开场靠后：它要用母版与 token 的最终值，早做等于重做。

### 10.7 如果工作台也要重绘

那是另一个量级：每个页面要布局、组件、状态、空态、明暗两套；图标系统 30–60 个。建议先交付「皮肤包三模块 + token 驱动的界面」，工作台重绘后置，用已有 R2 稿做基线，不重画整稿。

## 十一、命名：三层一套，不要一个名字打天下

### 11.1 三层各管一件事

| 层 | 用途 | 出现位置 | 约束 |
| --- | --- | --- | --- |
| 主题名 | 商店、皮肤列表、宣传 | 管理页卡片、封面 | 好念、能搜、不撞方舟词 |
| 角色代号 | 叙事身份 | 工牌、对话、开场 | 不能是代号式编号以外的昵称 |
| 型号 | 数据标识 | 包 id、日志、模型上下文 | 小写字母开头，3–64 位，仅字母数字短横线 |

### 11.2 四个方向

| 方向 | 候选 | 气质 | 风险 |
| --- | --- | --- | --- |
| 机构名 | 冷杉 / 北纬 / 白塔 | 有世界观，能延展成系列（第二套叫「冷杉·夜班」） | 需要一句话解释它是谁 |
| 状态名 | 低照度 / 恒温 / 静默运行 | 最准的气质描述，像设备的工作状态 | 都是通用词，搜索会撞 |
| 资产名 | 单元-07 / 07 号资产 / 维护中 | 最贴「企业资产」命题 | 单独看不像主题名，得配机构名 |
| 技术梗 | 冷启动 / 待机 / 回滚 | 「冷启动」一语双关：冷色调 + 开机 | 可能被读成纯技术词 |

### 11.3 推荐：主题「冷启动」／角色「单元-07」／型号 `CS-07`

- 主题「冷启动」：既是开机动作，也是整套配色的性格。用户每次启动都会看到开场动画，名字和它要讲的事是同一件。
- 角色「单元-07」：工牌上印的就是这个，不用另起昵称。编号比名字更像企业资产。
- 型号 `CS-07`：包 id 用 `cold-start`，角色目录用 `unit-07`，日志里写 `CS-07`。
- 三处落地：工牌印 `CS-07`；设置页标题「冷启动 · 单元-07」；开场第一句「冷启动完成。单元-07 已就绪。」

备选：「低照度 · 单元-07」更安静，适合走深夜陪伴；「冷杉 · 单元-07」更像一家真实机构，适合后面出系列。

### 11.4 命名自检四条

1. 说得出口：「我用冷启动那个皮肤」——不拗口、不需要解释第二遍。
2. 缩到 64px 还认得出：名字最终是要印在 18×24 的工牌上的。
3. 搜一下没有同名产品，尤其不要和现成游戏角色或公司重名。
4. 去掉「莱茵」那一层之后仍然立得住——立不住说明借的是别人的东西。

## 十二、B 层：工作台重绘

2026-11-05 追加。用户确认 A+B。本节只定结构与取舍，关键稿见 `designs/mecha-workspace-v1/index.html`。

### 12.1 关键稿做到哪一步

一屏可点：侧栏、会话、资料侧栏、输入、状态栏，加一段 2.4 秒「冷启动」演出（可点任意处或 Esc 跳过）。深色为主、浅色为副。示例数据，不读真实会话，不调用模型。

### 12.2 信息架构：骨架不动，换世界

沿用 R2 的区域划分，只替换表达方式。**功能语义不变，是重绘的前提。**

| 区域 | R2 档案暖白 | 冷启动 | 规则 |
| --- | --- | --- | --- |
| 导航 | 索引页、折角 | 档案编号索引（`A-114`） | 编号等宽，标题仍用正文体 |
| 消息 | 便笺 / 整理页 | 记录行（`001` / `002` 行号） | 行号是装饰，不参与交互 |
| 工具调用 | 墨迹扫过 | 等宽回执行（`✓ 完成 11ms`） | 必须有真实耗时或状态，不伪造 |
| 引用 | 资料签飞入 | `§` 标记 + 只读侧栏 | 点击才展开，不自动弹 |
| 等待 | 两轮墨迹 | 青色常亮 / 琥珀脉冲 | 脉冲表示「在处理」，不是进度百分比 |
| 完成 | 归档便笺 + 落印 | 一行自检回执 | 只响应当前会话，历史不补播 |
| 开场 | 开卷 3.9 秒 | 冷启动 2.4 秒 boot log | 可跳过，且不阻塞输入 |
| 角色位 | 导航底部肖像 | 观测窗头像 + 维护周期 | 角色不占正文 |

### 12.3 要重绘的组件

| 组件 | 数量 | 状态 |
| --- | --- | --- |
| 导航项与分组头 | 3 类 | 选中、悬停、键盘聚焦 |
| 消息行 | 2 类（使用者 / 单元） | 流式、完成、中断 |
| 工具调用卡 | 1 类 | 执行、完成、失败 |
| 引用标记与侧栏 | 2 类 | 只读、可关闭 |
| 输入区 | 4 件 | 空、有草稿、附件、发送中 |
| 状态灯 | 2 态 | 已回复、执行中 |
| 空态 | 4 个 | 新会话、无搜索结果、连接中断、需处理 |
| 外观抽屉 | 1 | 明暗、动效、减少动态 |
| 图标 | 30–60 枚 | 24px 画布，1.5px 线宽 |

### 12.4 与 A 层共用一套 token

工作台不另起一套色。`theme` 模块的 60–80 个 token 就是工作台的 token 源；两套色会让「主题换了但界面没换」露馅。角色只在导航底部与开场出现。

### 12.5 B 层带来的资源增量

- 图标系统：30–60 枚，内联 SVG 或一个图集，不占皮肤包的 32 个位置（B 层不进包）。
- 背景、网格、扫描线、状态灯：全部用 CSS 程序生成，不出位图。
- 角色与开场：复用 A 层母版和 startup 素材，不新增。

### 12.6 设计工作量估算

| 阶段 | 人日 |
| --- | --- |
| tokens 与基础元件 | 1.5 |
| 会话主界面 | 2 |
| 工具调用与引用 | 1.5 |
| 资料侧栏 | 1 |
| 空态与异常 | 1 |
| 外观与设置 | 1 |
| 冷启动演出 | 1 |
| 响应式与键盘路径 | 1 |
| **合计** | **约 10 人日** |

接入真实 DSH 的逐区适配另算，不在这个数字里。

### 12.7 已定的四个取舍

1. 深色为主。桌宠和长时间使用都在暗环境；浅色保留，但不作为默认。
2. 等宽字体只承担编号、时间、状态回执。「仪表感」来自克制，不是全篇等宽。
3. 青色不做按钮主色，只做状态与发光。大面积青色会让整体立刻变廉价。
4. 正文区不放扫描线、网格与故障效果。科技感只出现在开场、空态与状态灯，阅读区域保持安静。

## 十三、让桌宠更像真人：素材与行为增量

2026-11-05 追加。用户问「更像真人还需要哪些素材」。先分清两种含义，否则会花错钱。

### 13.1 两种「像真人」

| 方向 | 含义 | 成本 | 建议 |
| --- | --- | --- | --- |
| 行为像活人 | 有微动作、会看你、有延迟、有状态 | 中，主要是分层与逻辑 | 主攻这个 |
| 画风更写实 | 从二次元走向半写实 | 3–4 倍，且与科研企业风的平面感冲突 | 不建议 |

### 13.2 真人感从哪来（按投入产出排序）

1. **时序的不确定性**：间隔不均匀、反应有延迟、偶尔做一半停住。零素材，改逻辑。
2. **微动作**：眨眼、呼吸相位、重心左右转移。少量素材，收益最大。
3. **视线**：她看不看你，比她说什么都重要。
4. **声音**：呼吸、布料、伺服。合同目前没有声音通道，属于能力缺口，不是素材缺口。
5. **状态**：困、累、刚醒，会让同一套动作演出不同质感。

### 13.3 素材增量清单

| 素材 | 用途 | 规格 | 优先级 |
| --- | --- | --- | --- |
| 眨眼 | 打破静止 | 3–5 帧，2–6 秒随机 | 高 |
| 呼吸循环 | 已在做 | 2.5 秒，可随机相位 | 已有 |
| 重心转移 | 站立不僵 | 左右各 1 段，约 4 秒 | 高 |
| 头部转向 | 回应注视 | 左/右/回正，各 0.6 秒 | 高 |
| 视线方向 | 看鼠标/看窗口 | 观测窗亮度或扫描偏移 4–8 向 | 高 |
| 次级运动 | 发梢、裙摆、线缆滞后 | 2–3 段可叠加循环 | 中 |
| 手部微动 | 握拳/松开 | 2 态 | 中 |
| 表情扩展 | 打哈欠、困、惊讶、思考 | 在 6 态基础上加 4 态 | 中 |
| 状态变体 | 正常 / 疲惫 | 只做 idle 与 walk | 中 |
| 反应闪 | 被摸、被拖、落地 | 各 0.2–0.3 秒，3–5 帧 | 高 |
| 过渡帧 | 动作衔接 | 每个动作 3–5 帧 | 高 |
| 音效 | 呼吸、脚步、布料、伺服 | 4–6 个，各 1–2 秒 | 低（无通道） |

### 13.4 关键技术：叠加，而不是堆动作

真人感不能靠「每个动作再做十个变体」，要靠**层叠加 + 随机相位**：

| 层 | 内容 | 播放方式 |
| --- | --- | --- |
| base | 站立或待机 | 常驻 |
| breathe | 胸腔起伏 | 独立循环，随机相位 |
| blink | 眨眼 | 随机触发，2–6 秒 |
| gaze | 视线偏移 | 跟鼠标或随机 |
| secondary | 发梢、裙摆 | 跟随位移与速度 |

一层 base 加四层微动作，组合出的变化远多于 20 段视频，而且能实时打断。这是目前视频路线做不到、但分层后几乎零成本的部分。

### 13.5 机械姬的特殊优势

人类角色要靠眉毛、眼睑、嘴角做微表情，机械姬只有一条观测窗。但观测窗可以参数化：亮度、扫描速度、色温、短暂故障。这比五官更容易做出「非人但真实」的感觉，也更容易与状态绑定。

### 13.6 不建议做的

- 每个动作做十个变体：维护成本爆炸，收益低。
- 走路做八方向：桌宠只有左右，正面与侧面两张够用。
- 追求写实渲染：会与整套平面企业风打架。

### 13.7 结论

如果只能加三样：**眨眼、视线、反应闪**。如果只能改一样：**把间隔改成不均匀**。后者不需要任何新素材。
