## 补齐顺序与交付标准

1. **先接入本次定稿素材。** 按实际入口核对主题图标、封面、头像、开场正片和静帧、桌宠动作与声音。录入资源用途、来源、版本与摘要。只有素材和宿主能力齐备的动作才开放，读书、喝茶等道具体验须具备完整动作链。校验清单与媒体，比较原有和更新后的角色比例、脚点、透明边缘和音量。
2. **按路线图收首版遗留。** 先对照已经接入的回复风格、反馈和模型完成回应，补可选共享人设、真实模型对照证据、高频工作区主题缺口及定稿素材所支持的自主动作。设置管理交互沿用主控规划，首套只补必要的字段、默认值、可用条件和对应入口。模式或模型映射、新自主玩法、制作器、上传和市场由主控按阶段安排。
3. **用真实入口复验。** 从系统原 DSH 图标冷启动，验证同窗开场、自然交接、首次点击进入和 Esc、自动开场关闭、静音和减少动态。检查头像和侧栏、聊天输入、模型菜单、代码/表格/工具卡、文件预览。验证桌宠待机、回应、已支持走路与转正、打断后恢复、连续调大小、开关、停用恢复和换肤。对工作反馈复验去重、切会话取消、允许安静。覆盖升级须读回授权、皮肤选择、每套覆写和全局偏好。
4. **交给主控组织共同验收。** 交付素材对照表、改动清单、包与摘要、可复现构建入口和实机回执。源码检查、隔离官方客户端、日用实机、真实模型与用户结论各自登记，注明平台、宿主、插件和皮肤版本。Mac 与 Windows 的结论分别取得。以此前共同验收发现过的冷启动首击、侧栏覆盖、连续拖动与设置保存为回归重点。[早期共同验收记录](first-skin-independent-retest-2026-11-04.md)

接手先回报三件事：实际拿到的首套素材、计划补齐的功能位、准备使用的构建和实机组合。已有素材和运行证据可直接复用。日用安装、模型实际调用、提交推送及发布按用户或主控当轮明确的操作范围执行。
